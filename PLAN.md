# Blockwright — plan

Native ANSI/IRC art editor. C++20, Qt 6 Widgets, Linux first, then macOS and Windows.
Feature baseline is Moebius; the additions are what IRC block art needs:
layers, script-generated layers, a live IRC byte budget and a craft lint built into the editor.

## 1. Goals and non-goals

**Goals**
- Moebius-level drawing tools, keyboard-first.
- Layers as real composited stacks, not draw-order functions.
- Generator layers: a script produces cells, the editor shows the result as a layer, re-runs it when parameters change.
- Our own project format that holds layers, scripts, references and metadata.
- Export `.ans` (with SAUCE) and IRC `.txt` (mIRC codes) that fit IRC line limits, checked live while drawing.
- A headless CLI from the same core, so scripts can render, check and export without the GUI.

**Non-goals for v1**
- Collaboration server (Moebius has one; nobody here uses it).
- RIPscrip, PETSCII, Sixel.
- Animation (see Phase 8).
- Bitmap font editor.

## 2. Why build it (what Moebius lacks)

- Unmaintained: last release 1.0.29 in April 2021, Electron 28, crashes on Ubuntu 24.04 (#245).
- No layers (#148), no TheDraw fonts (#226), no 24-bit editing (#157), no UTF-8 import (#160).
- Its UTF-8 export has a light-grey-becomes-white bug (#173).
- It opened our pieces as blank canvases when the SAUCE FileSize was 0.
- Nothing knows about IRC: no byte meter, no mIRC export, no preview of how a line gets cut.

Icy Draw (Rust, egui) is the closest modern editor and has layers, TDF fonts and Lua.
It is the reference design for layers and the file format, not a base to fork.

## 3. Lessons from our ANSI projects

These are what make it more than a Moebius clone.

| Lesson (source) | What the editor does about it |
|---|---|
| Half-block pixels and ░▒▓ shade cells collide: a pixel plotted into a shade cell leaves a fallback speck; outlines break shading; `plot` erases text | Separate layer kinds: **pixel layer** (2× vertical resolution, resolved to ▀▄█ at composite time), **cell layer** (glyph + fg + bg), **text layer**. Compositing rules are defined once, in the core. |
| Every piece ends with hand-written byte-budget hacks: iCE space runs, ▀/▄ flips, "settle to left neighbour" (`downfall-of-numenor`, `funkpower-joust`) | **Live per-row IRC byte meter** in the gutter, red past the budget. The optimisations become export options, not scene code. |
| Raw `.ans` line length overstates IRC cost by 50–100 bytes; budgets were measured three different ways | One encoder (Blockwright's own, in `core/`) is the only source of truth for byte counts, in the meter, the lint and the export. |
| Budget is 407 bytes per line on EFnet via WeeChat; 512 minus `:mask PRIVMSG target :\r\n` in general | Budget set per project: preset "EFnet/WeeChat 407", or computed from a nick mask + channel. |
| Lettering most often fails on a letter that misreads at 1× (C/G, R/A, 0/D) | A **1× preview dock** that is always visible, plus an "IRC view" rendered in the mIRC palette with WeeChat's cuts. |
| Speckle, stray cells, same-colour merges, dotted diagonals and flat areas spoil a piece | **Lint panel** running the lint rules live, each finding clickable to its cell. |
| IRC drops trailing black cells and blank edge rows, so frames on the last column vanish | Lint warning + export option to pad with black-on-black █. |
| `• ★ … ► “”` have no CP437 code and save as `?` | Glyph picker only offers mappable glyphs in CP437 projects; lint flags any that slip in. |
| Shading ladder: dither only between ramp neighbours, 1–3 cells per rung | Shade brush and gradient tool walk a named **ramp** (fire, sunset, ice, steel, skin), never arbitrary colour pairs. |
| Mirrored shapes come out a cell off with half-to-even rounding; small circles need tuned radii | Shape rasterisers in the core with tests for symmetry; mirror mode is a canvas transform, not a re-draw. |
| A piece is worked as named layers, each looked at alone and in partial stacks | Layers keep that model, and an imported scene (§7) opens with each of its layers an editor layer. |
| A piece carries notes, a log and earlier versions | Project format has room for notes and versions/snapshots (§6). |

## 4. Architecture

```
blockwright/
  core/      C++20 library, Qt-free except QtCore types where it helps
             cell model, palettes, CP437 tables, layers + compositor,
             ANSI/SAUCE/XBIN/mIRC/UTF-8 codecs, shape rasterisers, lint,
             project I/O (libzip, zstd)
  render/    glyph atlas + canvas renderer interface (QPainter first)
  app/       Qt 6 Widgets GUI: tools, docks, undo stack, preferences
  cli/       headless: render PNG, convert, lint, export, run generators
  tests/     Catch2; golden files from funkpower's pieces
```

- **Cell model:** codepoint (Unicode internally, CP437 mapping at the edges), fg/bg as palette index *or* RGB, attribute bits, transparent flag.
- **Renderer:** pre-built glyph atlas per font, `drawImage` from source rects, dirty-region repaint, integer zoom with smoothing off. Behind an interface so a `QRhiWidget` shader renderer can replace it if large canvases get slow. Avoids the GPU-driver problems that hit Moebius (Electron) and Icy Draw (wgpu). In `render/`: `CanvasRenderer` (the interface) and `AtlasRenderer`, which keeps a 1× cache filled from a `GlyphAtlas` (256 glyphs × 16 palette colours, 24-bit colours made on demand) and repaints only the cells marked dirty; views scale the cache by the zoom. Views draw in view pixels, each a whole block of `max(1, floor(dpr))` device pixels starting on the first whole device pixel inside the widget (`app/device_grid.h`), so under fractional display scaling (1.25, 1.5) every cell still covers a whole number of device pixels at every zoom and the 1× preview shows one block per canvas pixel; at 1.5 that makes the art a little smaller than the UI around it. It must draw exactly what `renderCanvas` (the CLI's PNG renderer) draws, and the tests compare the two.
- **Undo:** `QUndoStack` with commands that store cell deltas per layer (a live text layer's text, settings, face and style stack undo as property commands instead, §15). The deltas are `CellEdit`s from `core/` (`edit.h`): keyboard edits are core functions that return one plus the next cursor, and the canvas view sends every edit through one `commit()`, which pushes it on the document's stack as one command (one per key; an edit that changes no cell is not pushed). Undo and redo repaint only the cells the edit changed and put the cursor back where the edit was made or left it. The modified flag is the stack's clean state: save marks it clean and open/new clear the stack, so undoing back to the saved cells clears the flag. Edit > Undo/Redo use the platform keys (Ctrl+Z, Ctrl+Shift+Z / Ctrl+Y).
- **SAUCE, iCE and letter spacing** are document state with undo. File > SAUCE... edits title (35), author (20), group (20), date (CCYYMMDD) and the COMNT lines (64 each, up to 255); the fields take only text CP437 can store, and OK waits until every field fits. A field (or the comment block) left as shown comes back byte for byte and is not checked, so a malformed date from a file (`00000000`) doesn't block editing the rest, and trailing blank comment lines from the record stay. View > iCE Colours and View > 9 px Letter Spacing are checkable. Each change is one undo step (`FormatCommand`, the SAUCE record and iCE before and after), so it sets the modified flag; the record's other fields (font, aspect, the flags not being changed) are kept, and a dialog accepted unchanged adds nothing. iCE follows Moebius and PabloDraw: blink and a bright background are one bit (`iceCell` in `core/`), so the cells stay as drawn and the toggle changes how they show and save. With iCE off a bright background shows as blink on its dark colour, drawn in its visible phase as `renderCanvas` draws blink, and saves as SGR 5; with iCE on a blink cell shows and saves as the bright background. A file whose iCE flag is off but which sets bright backgrounds anyway (SGR 100–107) opens with iCE on, as `writeAnsi` and `cli render` already treat it; its blinking cells lose the blink on open and keep their dark background, as `writeAnsi` writes them and `renderCanvas` draws them, and until the next save, saving warns that that many cells lost their blink when the file was opened with iCE colours and that the save doesn't put it back, and is refused from `saveFile` unless lossy saves are allowed. The open marks each lost cell (`Cell::lostBlink`, an editor-only bit inside the cell, #82), and `Document::encode` counts the marked cells the save still writes without a blink (`lostBlinkCount`, which `cli shade` uses too). Moved and copied cells keep their own mark (a paste, a stamp, a move, a flip or a turn, `CellEdit::moves`), so the mark goes where the cell goes: a lost cell moved, flipped, rotated or pasted stays lost, one made to blink again (in place or after a move) is back, and undo and redo restore the cells and their marks with them. A cell the edit lifts leaves a blank behind, so its claim goes with it: flipping a lost cell with its look-alike moves the claim and doesn't copy it. A drawn cell carries no mark of its own, whatever the brush built it from (colorize recolours the cell itself, despeckle copies a neighbour): `settleLostBlink`, which `Document::edit` and `cli shade` run on every edit, clears it on every drawn cell, so no other cell stands in for a lost one: a cell elsewhere that happens to save as the lost cell did, or that the flip of a selection puts in its place, earns it nothing. The mark lives only in the editor: no file, export, renderer or lint reads it, and `Cell::operator==` leaves it out, so cells that look the same are equal to lint, previews and tests; the edit builders compare with `identical()`, which sees it, so moving a lost cell onto one that looks the same still moves the mark. An edit that writes over a lost cell ends its claim: erasing it, drawing something else on it, shading or recolouring it is the artist's own edit, not a loss the open caused. The one exception is a cell, drawn, pasted or moved, that the save writes alike with the lost cell it covers when that cell stays put (`writesAlike`: the same CP437 byte, so ß and β are one glyph, the same palette colours and blink bit, other attribute bits ignored): it keeps that cell's claim (`writtenOver`), since nothing the artist can see changed. A cell an edit changes twice (mirror mode) is judged against what it was before the edit. A lost cell drawn over blinking with iCE on saves as the bright background iCE shows, which is what the artist sees, so it doesn't count. Copying a lost cell copies the mark, so each copy counts while it doesn't blink, and the count can be more than the cells that lost their blink on open. The count holds until the next successful save, after which the file written has no blink left to lose; reopening a file or New resets it. The warning says nothing about the original file, which a save to a new path leaves alone. Blink with iCE off hides and shows the foreground, so on a blank glyph (a space, NUL or 0xFF) it shows nothing: neither the open (`openAsEditor`) nor `writeAnsi` counts it as lost, and `cli convert` and `cli shade` write such a file without `--allow-lossy`. `writeAnsi` doesn't trim a trailing blinking space as a blank when it writes without iCE, so a bright-black background survives an iCE-off save; with iCE on the blink is dropped and the space is trimmed like any black space, as the editor writes it. 9 px redraws the canvas, preview and zoomed view with 9-px cells; turning 9 px on for a canvas too large for the 1× cache at 9 px leaves it at 8 px with a status-bar message, and opening a file that asks for 9 px and is too large at 9 px is refused, like any canvas too large to display. None of the three has a shortcut.
- **Keyboard mode** follows Moebius:
  - F1–F10 type the glyphs of the current F-key set in the pen's colours. The sets are Moebius's 16 (from PabloDraw, `core/glyph_sets.h`), all CP437 glyphs `.ans` can hold; set 6 (░▒▓█▀▄▌▐■·) is the default. Ctrl+, and Ctrl+. step to the previous and next set (wrapping), Ctrl+/ goes back to the default, and Ctrl+Shift+F1–F10 pick sets 1–10; sets 11–16 have no direct chord and are picked from the Glyphs menu, which lists all 16, or by stepping. The status bar shows the current set and its tooltip the keys.
  - The direct chords deviate from Moebius on purpose. Moebius uses Alt+F1–F10 and Alt+Shift+F-keys, but desktops take those before the editor sees them: Alt+F4 closes the window on GNOME, KDE Plasma and Xfce, and Alt+F2/F5–F8/F10 are GNOME window commands (Alt+F6–F11 on Xfce, Alt+F3 on KDE). Ctrl+F1–F4 switch desktops on KDE (Ctrl+F1–F12 on Xfce), and Ctrl+Alt+F-keys switch Linux VTs. None of the three desktops binds Ctrl+Shift+F-keys by default. On macOS Qt maps Ctrl to Cmd, so the chord is Cmd+Shift+F-key (with fn on keyboards whose top row defaults to media keys); macOS binds Control+Shift+F6 but no Cmd+Shift+F-key. A test keeps every shortcut off Alt+F-keys and bare Ctrl+F-keys.
  - The palette dock shows the 16 colours and the pen: a left click picks the foreground, a right click the background. Ctrl+Up/Down step the foreground, Ctrl+Left/Right the background (wrapping), Ctrl+D resets the pen to grey on black.
  - Typing on the last column leaves the cursor there, past the glyph: Backspace then clears that cell instead of the one to its left, and any move ends it.
  - A key is text when it gives printable text, unless Ctrl or Meta is held without Alt. So AltGr (Ctrl+Alt on Windows) and macOS Option characters type, and Ctrl/Cmd chords stay shortcuts.
- **Tools:** the canvas view hands mouse and key events (in cells) to the active tool first; whatever it doesn't take goes on to keyboard mode. A `Tool` (`app/tool.h`) has an id and a name, `activate`/`deactivate`, `mousePress`/`mouseMove`/`mouseRelease`/`keyPress` returning whether it took the event, `cancel` (drop what is in progress without an edit), `cancelDrag` (end a drag the mouse can no longer finish, without an edit), `dragging` (whether a drag is in progress), `settingsChanged` (the view's mirror mode or selection changed: a drag in progress redoes its edit and preview) and `finish` (write it as an edit), `paintCells` for cells in progress (drawn over the canvas, under the reference image and guides), `paint` for its marks (over everything but the cell cursor) and a `changed` signal. It edits through `CanvasView::applyEdit`, so every edit is one undo command and mirror mode applies to it; a tool that has already mirrored its edit (the drawing tools) passes `mirrored` so the view doesn't mirror it again, and `CanvasView::mirrored` gives a tool the view's mirror of an edit for its preview. The view calls `cancel` when the document changes under the tool (undo, redo, an edit the view didn't push, a new canvas). It calls `cancelDrag` when it loses focus during a drag the tool took, a popup opening included: a floating selection being dragged goes back to where the drag picked it up and stays floating, and a new selection rectangle ends as far as it got. A popup that opens during a mouse drag (the mouse's or the pen's synthesized mouse events) ends the drag at once, as focus loss does, with no edit: once the popup has had a mouse event Qt no longer sends the drag's release to the canvas, so the drag can't be carried on after it closes. A stylus stroke driven by tablet events goes on: Qt sends the pen's tablet events to the canvas, popup or not, so its own release ends it. That holds for a menu opened from the keyboard too: Alt+F takes the focus for the popup and then for the menu bar, and neither ends the stroke (#47), nor does Alt tapped alone, which takes it for the menu bar; a mouse drag ends at the first. While the menu bar has the focus the canvas sees no focus-out, so the view watches the application's focus: the focus going anywhere but back to the canvas, the menu bar or a menu (a window switch, a dialog, another widget) ends the stroke with no edit, and the window passes the undo key to the view, which ends the stroke and undoes nothing else. A floating selection with no drag in progress stays, so the menus can still act on it. The undo key during a selection drag ends it the same way and undoes nothing, as it does for the drawing tools. It calls `finish` before an edit of its own (typing, Backspace, Delete, F-keys), which then lands on top, and the window calls it before Save and Save As write and before the unsaved-changes check that New, Open and closing the window make. So a floating selection is stamped before any save or unsaved-changes check, and stays stamped (an ordinary undoable edit) if the user then backs out: Cancel on the unsaved-changes prompt, the Open dialog or the lossy-save warning, or a lossy save that is refused. A paint that throws leaves the rest of that paint out (the canvas too, if the renderer threw) rather than escaping `paintEvent`; the cell cursor is still drawn. A `ToolRegistry` holds the tools and the active one; the Tools menu is built from it (Keyboard Ctrl+K, Select Ctrl+E, and the drawing tools below). A `ToolEvent` carries the cell and, for the pixel tools, the half-block row under the pointer (`halfRow`, twice the cell row plus one in a cell's bottom half). A tool's `status()` text shows in the status bar while it is active.
- **Selections** (`core/selection.h`, `app/select_tool.h`): a rectangle for now, with a mask possible later behind `Selection::contains`. The selection belongs to the view (`CanvasView::selection`, `selectionChanged`), which draws its outline, so it lasts across tool switches; a new canvas clears it. Drag to select; drag inside the selection or press an arrow to lift its cells into a floating selection, which is only drawn (as the stamp would leave the canvas, rendered at 1× and scaled as it paints) until Enter or a click stamps it as one edit; Esc ends any drag and puts it back, or deselects. A floating selection never outlives a change it didn't make: switching tools, typing or saving stamps it first, and so does the unsaved-changes check, so a paste on a clean canvas counts as an unsaved change; undo, redo or a new canvas cancels it, leaving the canvas as the undo left it and the selection on the cells it was lifted from (or none, for a paste). Ctrl+X/C/V cut, copy and paste through the tool's own clipboard (cells with colours; nothing goes to the system clipboard); a paste floats at the cell cursor. Delete clears the selection (in keyboard mode it still clears the cell). The Selection menu has Select All (Ctrl+A), Deselect (Ctrl+Shift+A), Flip Horizontally/Vertically (Ctrl+Shift+H/V), Rotate Clockwise/Counterclockwise (Ctrl+R, Ctrl+Shift+R) and the paste mode: normal; transparent (the block's blank cells, a space or NUL on black without blink, don't write); under (only the canvas's blank cells are written). Flips remap the glyphs that face one way (▀↔▄, ▌↔▐, box corners and tees, slashes, brackets, arrows); rotation turns half blocks and box drawing a quarter turn (▀→▐→▄→▌) and keeps the selection's top-left corner. Glyphs that only flip turn in 4-cycles that make a half turn equal both flips for all 256 CP437 glyphs, and four turns the identity: brackets ( [ ) ], < « > », { ≤ } ≥, and ¬ ⌡ ⌐ ⌠ (« » flip sideways, ⌠ ⌡ upside down). For the three bracket cycles a turn and a flip don't commute as they would on a picture (Rotate Clockwise then Flip Horizontally makes ( a ], Flip Horizontally then Rotate Counterclockwise makes it a [), and no mapping can fix that: a vertical flip leaves those glyphs alone, so their half turn is just the sideways flip. Undo restores cells, not the selection.
- **Drawing tools** (`app/draw_tools.h`, Phase 2), in the Tools menu: Half-Block Brush (Ctrl+B), Shade Brush (Ctrl+Shift+B), Ramp Shade Brush (Ctrl+T), Form Brush (Ctrl+Shift+T), Soft Brush (Ctrl+Shift+N), Despeckle Brush (Ctrl+Shift+D), Glyph Brush (Ctrl+G), Colorize Brush (Ctrl+Shift+C), Line (Ctrl+L), Rectangle (Ctrl+U), Ellipse (Ctrl+Shift+O), Fill (Ctrl+J), Eyedropper (Ctrl+I) and Rim Light Brush (Ctrl+Shift+L), with Filled Shapes (Ctrl+Shift+F) toggling rectangle and ellipse between outline and filled. The same tools sit on a Tools toolbar. Smaller Brush (Ctrl+[) and Larger Brush (Ctrl+]) step the brush size a cell. Ctrl+Shift+U is left alone because IBus takes it for Unicode entry, and Ctrl+F is kept for Find; no two actions share a shortcut (a test checks it). Every one is a drag: it is previewed over the canvas and lands on release as one undo step, and the preview is the edit that lands: toggling mirror mode or Filled Shapes, or changing the selection, mid-drag redoes the preview at once. Esc drops it, and so does the undo key (Ctrl+Z) pressed during the drag, which undoes nothing else, even when there is nothing to undo; any undo or redo (from the menu or the stack), a format change (iCE, 9 px) and its undo or redo also drop it; switching tools lands it. Fill floods once, from where it is pressed; the release point doesn't move it. The preview renders only the cells the edit changes, and a filled shape recomputes only the shape on each move. The left button draws with the pen's foreground, the right with its background; the shade brush builds up one rung a pass with the left button and takes one down with the right (a space, ░, ▒, ▓ or █ moves, written in the pen's colours both ways, as Moebius does; text, ▀, ▄ and every other glyph is left alone, both ways), the glyph brush writes its glyph with the left and erases to a blank cell with the right, and the colorize brush sets the foreground with the left and the background with the right, keeping the glyphs. The glyph brush's glyph is █ until F1–F10 pick one from the current F-key set while it is active; the status bar shows it. The shade, ramp shade, form, soft, despeckle, glyph and colorize brushes paint with the Brush dock's settings (`BrushDock`, on the view like the pen): size (1–256 cells), square or round tip, strength, what a stylus's pressure scales (nothing, size or strength; size by default, which a mouse, always at full pressure, never changes), the ramp the ramp brushes walk (the named ramps, steel by default) and the alpha lock; the rim-light brush walks the same ramp. The dock also holds the light direction (eight compass points, NW by default), one setting that lights both the rim-light brush and the form brush, and for the shading brushes (§10) the form (dome, cylinder, plane), the form's rim light (off, labelled Form rim light so it isn't taken for the Rim Light brush) and glint (on), and the soft brush's hardness (0%); then the symmetry (off, mirror X, mirror Y, mirror X and Y, radial with 2–8 folds about the canvas centre or a set cell, its spins limited to the canvas and pulled in when a smaller canvas opens) and the pencil's 4-connected toggle. The half-block brush stays a one-pixel pencil. The ramp shade brush lightens along the ramp with the left button and darkens with the right; strength is the share of a whole colour (four rungs) a pass moves, rounded and never below a rung, so the default of 25% is one rung a pass and 100% a colour. Changing any of these mid-drag redoes the preview; the brush keeps the pen the drag was pressed with, so a pen change mid-stroke waits for the next one. A stylus drives the tool through `QTabletEvent` with its pressure in the `ToolEvent`; an event the tool doesn't take is left unaccepted, so Qt's synthesized mouse event handles it, and a release (which reads no pressure) lands with the stroke's last pressure; whether an event is a release is the view's call (below), not Qt's. The view decides the type and the button of every stylus tablet event by its own record of the pen's buttons (those of the pen's last tablet event at the view), not by Qt's, which an event the canvas takes through a popup leaves as it was: a release under a popup leaves the button held, so that Qt sends the next press as a move or as a press of the button that was let go, and a press under a popup comes again with the next event. A button the event holds that the record doesn't is pressed, one the record holds that the event doesn't was let go, and one both hold is held on. A button let go was let go at the event only if Qt says the event is its release; otherwise (Qt saw it go up elsewhere, or the event doesn't show) it was let go where the view last saw the pen. The view also keeps what it last knew of Qt's record, and whether Qt's tablet grab is its own (a press Qt sends it takes the grab, a release of the last button lets it go): with the grab and a popup open, an event comes through the popup, and Qt's record takes the buttons of every event but one the canvas takes that way. One no widget takes through the popup Qt passes again through the canvas's window, and so to the canvas, which sees it twice; the second time it is at most a button the tool declined, let go and pressed again, which the tool declines again. A button both records hold that Qt says is pressed went up out of view, so it was let go where the view last saw the pen, and is pressed again. An event Qt has the wrong type or button for that the tool doesn't take is handled by the view as the mouse event with the right ones would be (a press moves the cell cursor) and accepted, so Qt makes no mouse event of it with the wrong button; any other event the tool doesn't take is left unaccepted. A press Qt sent as a move sets no tablet grab, so its release can go to another widget; a button let go out of view lands the stylus's drag where the view last saw the pen. The view has tablet tracking on, so that happens as soon as the pen hovers back over the canvas, or at the latest when it presses on it again. The device whose press the tool took owns the drag until the drag ends, however it ends (a release, Esc, a lost focus or grab) and whatever buttons are still held: the stylus's tablet events, the mouse's events, or the mouse events Qt synthesizes from the stylus (a mouse event from a stylus device), when it was one of those the tool took. Another device's presses, moves and releases are ignored, and mouse events from the stylus during a tablet drag neither restart it nor add to it; during a drag the stylus's synthesized events drive, its tablet events stay unaccepted so Qt goes on making them. A drag the mouse's events drive (the mouse's, or the pen's synthesized ones) holds the mouse grab (`QWidget::grabMouse`) until it ends, however it ends: Qt sends a press's moves and release to the widget pressed only until a release with no buttons held, and another device's release is one, so without the grab the owner's later moves and release would reach no widget and the drag would stay live with no edit (#45). So another device's click elsewhere in the window comes to the canvas too, and is ignored there rather than taken by the widget under it. The grab follows the tool's drag wherever the drag ends: the view syncs it on every `Tool::changed`, which a drag ending emits, so a menu action that ends a drag (Paste, Cut, Delete, Select All, Deselect, a Library stamp, undo or redo, a new canvas) lets go of it too. A view that isn't shown takes no grab. A popup that opens during the drag keeps the pointer grab: Qt grabs for the popup before it tells the canvas the popup took the focus, which ends the drag, and on xcb the canvas's release ungrabs the pointer whatever window holds it, so the view sets the popup's grab again after its own grab or release, and a click outside still closes the popup. A drag driven by tablet events takes no grab: Qt sends the pen's tablet events to the widget its press went to, whatever the mouse does. Selections clip every tool: the view's selection becomes the stroke's mask (`selectionMask` in `brush.h`).
- **Half-block pixels** (`core/halfblock.h`, `core/shapes.h`): the half-block brush, line, rectangle, ellipse, fill and eyedropper work on pixels two to a cell. A cell holds pixels when it is a space, █, ▀ or ▄; plotting into any other cell replaces it, its background colour filling the other half. Cells are written in one canonical way: one colour is a space on a dark background or █ on black for a bright one, two colours are ▀ unless only ▄ keeps the background dark; two bright colours need a bright background (iCE). Every tool reads a cell by the colours it shows: with iCE off a bright background shows as its dark colour (and blinks), so the halves, the fill's colour test and the eyedropper all see the dark one. With iCE off a write puts the bright colour in the foreground, and when both halves would be different bright colours the half already there keeps its colour and the one being painted shows as its dark counterpart (only one bright fits; painting both halves of a cell gives the colour itself). A pixel write keeps the cell's other attributes (Blink included) and makes a transparent cell opaque; locked cells are never written. The pencil joins its points with 4-connected lines, or with 8-connected ones (`line8`, one pixel per step of the longer axis) when the Brush dock's Pencil 4-connected is off. A line is drawn the same whichever end it starts from (its ends are ordered top to bottom first). An ellipse is the box's pixels whose centres lie within the ellipse through the box's outer pixel centres, each radius r tuned to sqrt(r(r + 1)) so small circles read round (5 × 5 gives rows 3, 5, 5, 5, 3), and its outline is the filled pixels with a neighbour (of eight) outside, which is 4-connected. Fill floods the 4-connected pixels of one colour, through pixel cells only, so text and shades bound it. The eyedropper picks the half's colour in a pixel cell and otherwise the cell's foreground (left button) or background (right) into the pen.
- **Mirror mode** (Edit > Mirror Mode, Ctrl+M) turns symmetry on; Edit > Symmetry and the Brush dock pick what it repeats a stroke as: Mirror X (the default), Mirror Y, Mirror X and Y, or Radial (§10). Picking a mode turns mirror mode on, and Off in the dock turns it off; the mode is kept while it is off. The drawing tools repeat what they paint through the core's stroke options (`StrokeOptions::symmetry`), so the preview, the selection, the lock and the undo step treat the images as part of the stroke. The brushes repeat their dabs: each image is painted from the image cell's own value, with the tip and the glyph flipped as the image is, so the shade brush steps the image cell's own level, the colorize brush recolours the image cell's own glyph, and the glyph brush writes its glyph flipped (▌ as ▐ under mirror X). The shading brushes (§10) go through the same images: the form brush with nothing selected shades each image as its own form, from the cells that image has covered; the soft brush bands the cells all the images have covered as one shape, so images far apart band as the stroke alone would; the despeckle brush cleans each image's own cells. The pixel tools (half-block brush, line, rectangle, ellipse, fill) repeat pixels, not cells: an image pixel goes into its cell's own half and the other half stays as it was, and fill paints the images of the region it flooded. The selection and the lock clip each image on its own, so a stroke outside the selection still paints its image inside it. Edits made outside the drawing tools (typing, Backspace, Delete, paste) are a transform of the edit as before: in mirror X a change at column x is repeated at width − 1 − x with its glyph flipped horizontally, where the edit's own change wins on the mirrored cell; in the other modes they are not repeated.
- **Guides and reference image** are view overlays, never saved: View > Guides draws a line after column 80 and every 25, 40 or 50 rows; File > Open Reference Image… shows a PNG or JPEG across the canvas width at its own aspect, one scale both ways (only the part over the canvas is scaled, and each of its pixels is what the whole picture scaled by that factor has there: averaged when the picture is reduced, interpolated when it is enlarged; the cached copy is at most the canvas size at the current zoom and 2^24 px, drawn scaled up past that, with a row more where the picture goes on below the canvas by at least a whole cache row so its bottom edge blends as the whole picture does (by less, the last row is read again, as at the picture's own bottom edge), the same whatever part of the view is repainted; a reduced picture is read and converted at most 2^20 px at a time, a row wider than that in pieces; if scaling fails the status bar says so and it isn't retried until the zoom, canvas or image changes), with View > Reference Image to show or hide it, set its opacity (25–100 %) or clear it. It lasts the session; the project format's `refs/` (§6) will keep it.
- **Library implementation notes** (Phase 2c.2; the design is §12): `core/` `library.h` reads, writes and checks stamps; `app/library_dock.h` is the dock. A stamp is `<slug>.ans` (at most 400 × 5000 cells, as `.ans` parses; SAUCE title = its name: 1–35 CP437 bytes, no NUL, not ending in a space, checked when written and when read; 0x01–0x1F are glyphs here, ☺ ♥ …) beside `<slug>.json`, which holds exactly `{"category": "...", "tags": ["...", ...], "ircBytes": N}`: a non-empty category; tags may be none, but no tag is empty or holds a comma; neither holds a control character; N is the IRC bytes of the widest row as `irc::encodeCanvas` encodes the `.ans` as it parses. Any other key, a key given twice, a wrong type, an N that disagrees with the art, or art whose cells are all blank is refused. Libraries are directories scanned recursively; an art file is any `.ans` with the extension's ASCII case folded (`X.ANS` too), paired with `X.json` or, failing that, an `X.json` in any case, the same rule Save to Library's slots use; a symbolic link to a file is read through, one to a folder is not followed. That rule keeps a link from being followed by accident; it is not a security boundary (a folder swapped for a link between being listed and opened is followed, and whoever can do that inside the user's library can already write stamps there). Files are read through the opened handle: on POSIX it is opened non-blocking and refused unless `fstat` says regular file, so a FIFO swapped in after a path check can't block the reader. A `.ans` without a sidecar, a sidecar without a `.ans`, a stamp that fails the check, a broken link, a link to a folder, a folder that can't be read, and a `.ans` or `.json` that isn't a regular file (a FIFO, a device; never opened) are listed as problems (a file in a folder that can be listed but not searched is "can't be read") (`library list` and the dock's status show them as warnings, `library check` fails on them). The bundled library is `<prefix>/share/blockwright/library/` (found from the binary's directory; the repo's `library/` installs there). The user library is `QStandardPaths::GenericDataLocation` + `/Blockwright/library`, the same for the GUI and the CLI: on Linux `~/.local/share/Blockwright/library`, which on Linux and macOS is the GUI's `AppDataLocation` + `/library`; on Windows it is under `AppData/Local`, not the roaming `AppData`. `BLOCKWRIGHT_BUNDLED_LIBRARY` and `BLOCKWRIGHT_USER_LIBRARY` override them. Placing a stamp (double-click, Enter, or a drop on the canvas) stamps whatever already floats, in its own mode, and floats the stamp's cells at the cell cursor or the drop cell through the paste path in transparent mode for that float only (`SelectTool::floatBlock` with a mode): the Paste Mode setting is not changed, the Selection menu shows the float's mode while it floats, and a Paste Mode pick during the float applies to it and becomes the setting. Selection > Save to Library… writes the selection, or the floating selection, without stamping it, with the document's iCE (cells as `Document::encode` writes them), and refuses cells `.ans` can't hold and an all-blank block. The file is `<user library>/<slug>.ans`, the slug being the name's ASCII letters and digits (lower case, `-` between runs, at most 48), or, for a name with none, its glyphs' code points (`♥` is `u2665`); of `<slug>.ans`, `<slug>-2.ans`, `<slug>-3.ans`, … the one holding a stamp with the same title is replaced, after asking; otherwise the lowest one with no `.ans` or `.json` of any kind is used, so a name never replaces another title and is never saved twice. File names are compared with ASCII case folded (on a case-insensitive volume `OAK-TREE.ans` is `oak-tree.ans`; a same-titled one is replaced under its own name), and the chosen new name is checked to be free just before it is used. A library folder that can't be listed is refused rather than taken as empty. Paths stay native (`std::filesystem::path`) from the scan to the write, and the dock identifies a stamp, in lookups and in its drag payload, by its path's native bytes; a drop is placed only if its payload is the key of a stamp in the current scan (it is never decoded into a path, since any application can offer the MIME type), so file and folder names that aren't UTF-8 are written as themselves and never mistaken for one another. Both files are written to temporaries first and then renamed into place, sidecar first, so a failure leaves the old stamp as it was (if the last rename fails the old sidecar is put back, and the error says if that failed too); a `.ans` or `.json` that is a symbolic link, or anything but a regular file, is refused rather than written through. A replaced file keeps its permission bits (0777 only: set-user-ID, set-group-ID and sticky are not kept; a new file gets 0666 less the umask), and a write that fails part way removes its temporary file and closes its descriptor. Thumbnails are `renderCanvas` at 1×; one that doesn't fit the 96×64 icon box is scaled down by averaging the 1× pixels under each icon pixel, rendered a band of rows (about 2^22 px) at a time so a large stamp's whole 1× image is never held. Only the icon is cached, in memory, keyed by the cells and glyph width it draws, and a rescan drops the icons of stamps that changed or are gone. `blockwright-cli library list [dir]` prints one stamp a line, tab-separated: category, name, width x height, widest IRC row in bytes, tags (comma-separated, which is unambiguous because a tag can't hold a comma), path; with no dir it lists the bundled then the user library, and problems are warnings (exit 0). `blockwright-cli library check <dir>` reports every problem, and any stamp whose widest row is over the 407-byte budget, and exits 1 if there was one. The bundled set (Phase 2c.3) is `library/<category>/<slug>.ans` beside its `.json`, in eight categories (trees, sky, land, water, fire, smoke, buildings, frames), every stamp signed funkpower; a test holds each one to the IRC budget and to the shape rule: trimmed to its part (a drawn cell on every edge) and, unless it is a frame, at least one blank cell on its outer ring, so it is never a filled rectangle; a frame instead has an opening: its centre cell is blank, and the blank region joined to it stays inside the ring and covers at least half of the cells within it. A stamp drawn only in black (a silhouette) is tagged `silhouette` and `dark`, since its thumbnail on black shows nothing.
- **Fonts:** bundle the CP437 VGA 8×16 / 9×16 family first; Amiga fonts later once their licences are checked.
- **Build:** CMake + Qt 6.8 LTS (6.4 is the minimum, for distro LTS releases), `vcpkg` or system Qt on Linux. No Rust toolchain and no submodules: the IRC encoder is C++ in `core/` (§8). CI on GitHub Actions for Linux; macOS/Windows jobs added in Phase 6.

## 5. Layers

Modelled on Icy Draw's layer record, trimmed to what we need. In the core: `layer.h` (the model and the stack) and `composite.h` (the compositor).

| Property | Notes |
|---|---|
| id | `LayerId`, unique in the stack and never given again, so undo and the project file can name a layer across adds, removes and moves; ids read from a file are kept and new ones go above them. `nextId` only moves up and is 0 for good once the last id is taken; the manifest saves it (`reserveIds` restores it), so a removed layer's id (and its `scripts/<id>/`) isn't reused after a reload |
| name | Free text |
| kind | `cells`, `pixels`, `text` (live text in a font, with a text style: §15); `generator` and `reference` (image, never exported) are reserved: the stack holds them, the compositor skips them. Generator layers will composite as cells from their cached output, saved in `.cells`, so a reader without the generator still composites and exports them |
| offset x/y, width/height | Layers can be smaller than the canvas, run off it and be moved; the offset is in cells (a pixel-row offset for pixel layers is deferred; if it comes it is an optional field defaulting to 0, not a format break) |
| visible, locked, alpha-locked | Locked and alpha-locked are for the tools (`layerPaintable`; alpha-locked is `StrokeOptions::lockTransparent` for cells and text layers, `layerStrokeOptions`, and per pixel on pixel layers, `layerPixelPaintable`); neither changes the composite |
| mode | normal, chars-only, colours-only (repaint colours without touching glyphs); pixel layers ignore it, but it is saved, and the layer panel greys it out for them |
| opacity rule | Cells are opaque or transparent; no blending, because the output is 16 colours |
| group | Deferred: the stack is flat for now; groups, when they come, are pass-through only |

- **Model.** A `Layer` is its `LayerProperties` (what `layers/<id>.json` will hold) and a `Canvas` of its own size (what `layers/<id>.cells` will hold); a new layer is all transparent cells. A `LayerStack` is the layers bottom first on a canvas of a given size, with add (at an index, on top by default), remove, move and find by id. `LayerStack::fromCanvas` is one opaque cells layer, "Background", which is how a flat `.ans` opens. Kinds and modes have stable names for the file (`layerKindName`, `layerModeName`).
- **Cells by kind.** A cells layer's cells are ordinary cells. A text layer's are too (a grid of characters for now); TDF live text (Phase 5) will add a source property that renders into those cells, so the compositor and the `.cells` file don't change when it lands. A pixel layer stores two half-block pixels a cell, each a palette colour or transparent: an opaque cell is a pixel cell as `halfblock.h` writes it with iCE on (both halves set), a transparent ▀ holds only its top pixel and a transparent ▄ only its bottom one (`layerPixels`, `pixelLayerCell`, `setLayerPixel`). So every kind is edited, undone and saved as cells through `CellEdit`, and `.cells` stores transparent cells in full (glyph and foreground: a transparent ▀/▄ is a pixel). `toLayerEdit` turns a tool's canvas-cell edit into the layer's own cells: changes outside the layer are dropped, each `before` is the layer's own cell (not the composite the tool saw), a cell changed more than once is one change to its last value, and changes that leave it as it is are dropped, so undo restores the layer exactly. `dirtyRect` gives the canvas cells to recomposite. A tool writing a pixel layer writes with `setLayerPixel` (keeping the other half) and checks each pixel with `layerPixelPaintable`.
- **Composite** is defined bottom-up per cell, in `composite.h` only. Each cell starts as the ground (a blank cell) and takes each visible cells, text or pixel layer over it in turn; a transparent cell adds nothing. A cells or text layer's opaque cell replaces the cell (normal), writes its glyph over the colours under it (chars-only) or its colours and attributes under the glyph (colours-only); nothing is re-picked, so 24-bit colours pass through. A text layer's cell (normal or chars-only) makes the cell text, and no pixel layer above covers it: plot doesn't erase text, whichever is on top. Being text goes with the glyph, so a cells layer above that writes its glyph (normal or chars-only) makes it plain cells again; an opaque space in a text layer is text and blocks pixels (Phase 5's TDF renderer should write a letter's empty background as transparent cells, not spaces). A `pixels` layer replaces the halves it sets and re-picks ▀/▄ with the right fg/bg (`halfBlockCell`, the background kept dark where it can be); a half it leaves transparent shows the half under it: a pixel cell's own half, the colour a shade mostly shows (░ its background, ▓ its foreground, ▒ its darker colour on top and lighter below, the colour a reader takes a cut shade for; context-free, so a cell depends only on itself) instead of the fallback that leaves a speck, and any other cell's background. Cells under pixels are read by the colours they show under iCE. With iCE off only one bright colour fits a cell, and the pixel, on top, keeps its colour: the half under shows dark, a shade's background (always dark with iCE off) or a pixel half's dark counterpart; two bright pixels of one layer keep the top's. This is the opposite of the half-block tools' rule (§4: the half already in the cell keeps its colour) on purpose: across layers the upper layer is in front, so its shape keeps its colours wherever it is moved. A half-covered cell keeps the under cell's blink only where the half under was blinking (it showed the foreground, a colour other than the background's) and keeps its colour: that half stays the foreground, written ▀ or ▄ as needed, unless the pixel is bright with iCE off and has to be; a half under that showed the background doesn't start to blink. A half-covered 24-bit cell is quantised, as the half-block tools do.
- **Incremental.** A composited cell depends only on the layers' cells at that cell, so `recomposite(stack, out, rect)` brings a composite up to date after an edit (its `dirtyRect`), a move (both bounds, united clipped to the canvas, `unite(a, b, canvas)`, so a far offset loses nothing), or a change of visibility, mode or place in the stack (the layer's bounds). 160 × 100 with 8 layers composites in about 1 ms on the dev machine, an 8 × 8 rect in about 4 µs.
- **Sample merged** toggle for the eyedropper and fill (Phase 3b).
- **Bake** turns a text layer into a cells layer (`bake`); a generator layer will bake its cached output the same way, and a styled layer its styled result (§15).
- Exports always flatten the visible composite (`flatten`).
- The done-when test (`test_composite.cpp`) puts black, yellow and red pixel shapes, their edges on odd pixel rows, over a steel ramp field shaded down and across the canvas: the composite passes `lint::checkLadder` (speckle included) and the lint's noise score with iCE on and off, and in every cell a shape cuts, the covered half shows its pixel's colour and the free half the colour the half-block rule asks for (with iCE off, the dark colour where two bright ones would share the cell); plotting the same pixels into the flat field leaves 18 to 35 cells that don't. The ladder lint and the noise can't see those specks (a cut cell is a half block, off the ladder, and noise skips pixels beside shade cells), so the test checks them itself; a lint rule for them is a follow-up.

## 6. Project format

Single file, zip container (like `.ora`/`.kra`), extension `.bwp`, with an unpacked-directory form of the same layout for git and other tools. `core/include/blockwright/project.h` is the reference.

```
manifest.json      "format": "blockwright", "version": "1.0", width, height,
                   palette ("cga"), ice, ircBudget {profile, bytes},
                   sauce (null or title, author, group, date, font, comments,
                   letterSpacing 8/9/"reserved"/null, aspectRatio, tinfo3,
                   tinfo4, reservedFlags), layers (ids, bottom first),
                   nextLayerId
layers/<id>.json   layer properties (LayerProperties) and size
layers/<id>.cells  binary cell data (versioned, zstd)
scripts/<id>/      generator source + params.json + cached output
refs/              reference images
notes.md           brief, plan, notes; absent when empty
snapshots/r<N>.ans saved rounds, each the composite flattened to .ans
thumbnail.png
```

- `.cells`: `BWCL`, u16 version (1), u16 reserved (0), u32 width, u32 height, then one zstd frame of width × height 14-byte cells row by row: u32 code point; fg and bg as u8 kind (0 palette index, then index and two zeros; 1 RGB, then r, g, b); u8 attributes; u8 flags (bit 0 transparent). Little-endian. Anything else is refused.
- Version is `major.minor`. Readers refuse unknown major versions instead of dropping data on re-save (Icy Draw's rule). Within a major a reader ignores keys and files it doesn't know; the files are kept byte for byte and saved back, the keys are not, so a minor version may only add what an older reader can drop without changing what the project shows. A repeated JSON key is refused.
- Paths are relative and `/`-separated; an entry with an empty, `.`, `..` or backslash, colon or control-character part, a part over 255 bytes or a path over 1024, an encrypted or oversized entry or a repeated one is refused. So are two paths a case-insensitive or Unicode-normalising disk takes for one (compared as NFD of the full case fold of NFD, so `ß`, `ẞ` and `ss` are one), a directory spelled two ways and a path that is both a file and a directory. Any entry that is not a plain file or directory is refused, hidden or not: a symlink, FIFO, device or socket in a directory, and in a zip any entry whose UNIX mode says so. Hidden files and directories (leading `.`) are otherwise skipped on read and left alone on a directory save. A directory read opens each file without following a link or waiting on a FIFO, and reads it only if it is still a plain file of the size the walk saw. Every layer file must be listed in the manifest and every listed layer must have both files.
- Limits, checked before anything is allocated or decoded: 10 000 entries, 256 MiB an entry, 1 GiB in all, 1024 layers, 2 000 000 cells a layer (the canvas limit) and 16 000 000 cells across the layers (about 256 MiB decoded), the last read from the `.cells` headers before any is decoded; 1 MiB for `manifest.json` and each `layers/<id>.json`, checked before it is parsed (a JSON parse takes about ten times the text).
- Writers encode the whole project first and refuse what a reader would refuse (the limits and paths above, and SAUCE text longer than its field) before the destination is touched, so a save or `snapshot` that would cross a limit leaves the original as it was.
- Zip saves are deterministic (fixed entry time; `.cells` and `.png` stored, the rest deflated) and replace the file whole. A directory save writes each file whole through a temporary file created exclusively (`O_EXCL`, `O_NOFOLLOW`, a random name) and renamed over it, the manifest last, then removes the files the project no longer has; it refuses a symlink at an entry or on a directory on the way to one, a non-empty directory with no manifest, and, before writing anything, a path (the directory's own included) longer than the system opens. A first save that fails part way removes what it wrote, so the retry isn't refused.
- A flat file becomes a project as the editor opens it (a non-iCE file with bright backgrounds turns iCE on, its blink dropped and reported). Its SAUCE keeps every field an `.ans` save keeps; the type, size and iCE flag are the project's.
- Snapshots and every export flatten the composite through the compositor and show each cell with the project's iCE, as the editor saves; the CLI refuses a lossy one unless asked.
- CLI: `pack` / `unpack` converts between zip and directory (or from a flat file to a project); `snapshot` saves the next round; `info` describes a project; every command that reads art reads a project as its flattened composite.

## 7. Scripts and generator layers

Recommended: **external-process generators first, embedded Lua later.**

- A generator is any executable that reads `params.json` + canvas info on stdin and writes an `.ans` on stdout. Black-on-black space is opaque; transparency comes from the layer's mask or a chosen key colour.
- Existing Python `ansidraw` scenes work unchanged: one scene layer becomes one generator layer.
- The editor shows parameters as a form (sliders, colours, ramps), re-runs on change, caches output in the project.
- Tradeoff: process spawn per run (tens of ms) and Python as a runtime dependency, against zero embedding work and full reuse of the scene's own Python.
- Phase 8: embedded Lua 5.4 via sol2 (MIT, header-only) for in-editor brushes and fast generators; sandboxed, no interpreter to ship. QJSEngine is the fallback if sol2's slow release pace becomes a problem.

(2) Where libansilove computes values past the palette we stay in it: bold on an iCE bright background (`1;5;31;44;7`) ORs the bright bit (libansilove adds it and reaches index 20), a repeated SGR 1 or 5 doesn't add 8 again, and a CUP row or column of 0 is read as 1 (libansilove computes -1). Plain digits too large for libansilove (`4294967296`) read as 0 and reset there too; here they are an unknown SGR, like `999`, and do nothing. (5) A cursor move with more than one parameter (`ESC[2;5C`) uses the first; libansilove's strtonum fails on the whole field and moves 1. **The IRC encoder** is Blockwright's own C++ in `core/` (`mirc.h`, `mirc.cpp`), so the meter, lint and export share one encoder. `encodeMircRow` writes a row of cells in mIRC colours as the shortest line that draws it: it searches every way of drawing each cell (a space as a block in its background colour, a half block as the other half with the colours swapped, a cell whose colours match as solid, and with `swapShades` ░ as ▓ reversed and ▒ as itself reversed), writes a colour number with one digit unless a digit follows, ends a colour code before a comma with `^B^B` where that is shorter than repeating the background, and ends a line whose last glyph is a space with `^O`. `nearestMirc` is the nearest of mIRC's 99 by squared RGB distance, the lower number on a tie. A code point that is not a Unicode scalar value or a colour over 98 throws `IrcError`; `irc::encodeRow` never passes either. `tests/data/golden-irc/` is the fixed oracle for its output.
- Export = Blockwright's parser (above) → canvas → the row encoder, so the CLI export, the editor's export and the meter all measure the same canvas. Export encodes the cells as they are: the 16-colour palette, since the parser quantises 256-colour (`38/48;5;n`), 24-bit (`38/48;2;r;g;b`) and PabloDraw `CSI t` colours to it as it reads them (the table above). A palette index maps to the mIRC colour of the same name and shade (the PC's dark red to mIRC brown, its brown to mIRC orange, its grey to light grey). The encoder also maps an RGB cell to the nearest of mIRC's 99, but no cell holds RGB until cells keep it (24-bit editing, §13 phase 8 "Later"). Transparent cells export blank, as `.ans` writes them, and a C0 control or DEL in a cell exports as its CP437 glyph (NUL as a space), never as a raw byte; a C1 control (U+0080–U+009F) exports as `?`, since some clients read `C2 9B` as a CSI. Trailing black spaces and the blank rows above and below the art are dropped as the ans2irc CLI drops them. Divergences from the ans2irc CLI, which parses the file itself: (1) colours: ans2irc keeps 256-colour and 24-bit colours and maps them to the nearest of mIRC's 99 (`38;5;208` → mIRC 53, `38;2;0;128;255` → 59), where Blockwright exports its 16-colour quantisation (mIRC 7 and 10), pinned in `tests/test_irc.cpp`; (2) every parse divergence above where Blockwright follows libansilove and ans2irc does not changes the IRC output too: ans2irc stops a CUF at the last column, libansilove (and Blockwright) at the width, so text after `ESC[nC` to the edge wraps differently, and the CR and TAB rules above (a CR doesn't move the cursor, a TAB can reach the width) give different rows for a file that relies on them. Over the library corpus, which has no 256-colour, 24-bit or `CSI t` colours, the CUF wrap is the only difference seen (1 of 509 files).
- `cli export --irc` encodes losslessly and never cuts: lines over the budget (default 407) are listed, and the file is not written (exit 3) unless `--allow-over-budget`. Fit-to-budget (least-visible colour merges, in C++ in `core/` like the encoder) is Phase 4.

## 9. Pipeline integration

- **Publish to library:** write `.ans` + `.txt` into the `ascii` repo's `funkpower/`, update `.tags.json` and `.dates.json`.
- **Send to WeeChat:** copy to a configured folder on the WeeChat host as `<slug>-r<N>.ans` and send `*/ascii reload` to the fifo.
- **CLI:** `render`, `lint` (the lint rules), `export --irc`, `run-generators`.
- **Same-file output:** `cli convert x.ans x.ans` rewrites the file in place through a temporary file (normalising a piece is a real use), while `export` and `render` refuse an output that is their input under any name, since they would put a different format over the source.
- Later: an MCP server over the CLI (Icy Draw ships one).

As built (phase 4c, `core/pipeline.h`, `app/publish.h`):
- **Both actions confirm:** each is a File menu dialog, then a question that names every file it will write (the library's four, or `host:dir/<slug>-r<N>.ans`), default No. Until a project format exists, "outside the project" means anything but the document's own file. An `.ans` that would lose data (`AnsiOutput::lossy`) is named in the question; the non-interactive calls refuse it unless allowed, as `saveFile` does.
- **Piece names** are 1–64 of `a-z 0-9 - _`, starting with a letter or digit, suggested from the file's base name (`Neon Skull (r3).ans` → `neon-skull-r3`). The key is `funkpower/<slug>`, as the ascii script builds it.
- **Publish** writes the `.ans` as Save would (a floating selection is stamped first, and Send does the same), the `.txt` as `export --irc` would, and the two indexes. The indexes are parsed strictly and written back byte for byte as the script's `json.dump(indent=1)` does (keys sorted, `\uXXXX` for non-ASCII and DEL, each file keeping whether it ends in a newline; the real library round-trips unchanged). A file the script would misread (a duplicate key, a value of the wrong kind, not UTF-8) is refused, not rewritten, and so is one laid out any other way (CRLF, another indent, keys out of order, trailing space), since writing it back whole would change it throughout. Tags are lowercased as the script's `str.lower()` does (Unicode, not only ASCII; only its word-final sigma rule is not followed, so a final `Σ` becomes `σ`), deduplicated, sorted and always include `funkpower`; a piece's tags already in the index are folded the same way when it is republished; republishing adds to a piece's tags and keeps its date, the day it joined the library. Publish refuses an IRC line over the budget (407 bytes) with no override, and refuses a piece the script would take for another file (the same name in another case, or as `.asc`). Every file is written to a temporary file beside it, created exclusively so nothing already at that name is written through, before any is renamed into place; a symbolic link or other non-regular target is refused. The plan records the four files' bytes and the piece's names as it found them, and Publish writes nothing if any has changed by the time the user confirms (another publish, an edit, a new clashing name), asking them to publish again. The library folder is remembered; nothing is committed or pushed.
- **Send** is one `ssh -o BatchMode=yes -o ConnectTimeout=10 <host> <command>` with the `.ans` on stdin (not scp): the command writes it to `<dir>/<slug>-r<N>.ans` through its own `mktemp` file (a dot name, removed by a trap if anything fails or the connection drops) and renames it into place only if all of its bytes arrived (the command is given the length; a dropped connection also ends `cat`'s input, so a short file is reported and the earlier round kept), then writes `core.weechat */ascii reload` to the running WeeChat's fifo (`${XDG_RUNTIME_DIR:-/run/user/<uid>}/weechat/weechat_fifo_<pid>`) under `timeout 5`, and prints `RELOADED` or `NOFIFO`; on `NOFIFO` the editor tells the user to run `/fifo enable` and `/ascii reload`. The host has no default and must be letters, digits and `. _ - @` (not starting with `-`); the folder defaults to `~/ascii/wip` and must be `~`, `~/…` or `/…` of the same characters, no `..`, so nothing reaches the remote shell unquoted. The host, folder and each piece's last round are remembered, and the round offered is the next one. The window waits for ssh (at most 30 s).

## 10. Advanced brushes (shading and detail)

The core of what an editor adds: the shading and detail moves of hand-made block art, done at the cursor. Each brush is a core-library function with tests, wrapped by a GUI tool.

**Shading**
- **Ramp shade brush:** lighten/darken one step along the layer's ramp per pass, using the ladder A → B░A → B▒A → B▓A → B. Never mixes colours that aren't ramp neighbours.
- **Form shading brush** (`brushes/form.h`): paint over a masked shape and it shades as a dome, cylinder or flat plane lit from the scene light vector, with rim light and specular as toggles.
- **Soft brush / falloff** (`brushes/soft.h`): size and hardness; the falloff becomes banded rungs 1–3 cells wide, not noise.
- **Ramp gradient tool:** linear and radial, cell-banded or 4×4 Bayer, along a ramp.
- **Blend/smudge:** pulls ramp values along the stroke and re-quantises to the ladder.
- **Despeckle brush** (`brushes/despeckle.h`): majority filter that removes isolated cells and stray shade fallbacks (the lint's speckle).

As built (phase 2b, part A):
- **Scene light:** the Brush dock's light direction (`BrushSettings::lightDirection`, a `Compass` point), north-west (top left) by default, the one light the rim-light brush also uses. It is a direction on the canvas, a row counting as two columns, raised towards the viewer (z 0.6) for the dome and cylinder. Until layers and a project file exist it is per session, not saved; the project format should keep it with the document so every form in a piece is lit alike.
- **Form:** `formRungs` gives each cell of a shape its rung. Each cell's depth into the shape is its exact distance to the nearest cell off it (`edgeDistance`, a row counting as two columns, a linear-time distance transform). A dome is a ball whose surface meets the shape's edge, its normal from that depth; a cylinder is round across the shape's shorter side on screen and straight along the longer, and a light whose part across its axis is under 0.3 of it is tilted to the diagonal it leans to across the axis (west of a pillar, north of a log when it leans to neither), so a light along the axis doesn't lay the whole form in one rung; a plane tilts towards the light. A dome or a cylinder with the glint on gets it as a spot on the lit side: the top rung on the most lit cell, a cylinder's ties going to the middle of its length, and its more lit neighbour in the row, where every cell it lifts above the plane and each of that cell's neighbours is on the shape at the plane's rung, so the glint never reaches the fall, the shadow or the edge; with no room for it there is none, and a plane has none. The form follows the craft rule for a round form: a broad solid lit plane, the whole fall of the ramp crowded at the turn, the shadow side down to black. Each cell's arc is its distance from the brightest point over the surface (the angle between its normal and the light's whole direction, across the canvas and out of it, times the form's radius; on a plane its distance along the light), so a north-west light falls diagonally and a north one from the top, not in columns or rows. The turn is a right angle from the light (on a plane the middle of its span). A try lays the cells nearer the light than the fall's start as the lit plane, solid (the top rung, or with a glint the highest solid rung below it, the glint coming up to the top through a rung a cell round it), then every rung below the plane down to the first above the darkest colour, each `band` columns of arc wide, and past the fall the darkest colour, black on a ramp that starts with it. A cylinder too thin for the ladder to come down to black from its plane has its shadow edge (the cells on its silhouette across the axis facing away from the light) black all the same, which the lint reads as ink ending the gradient; not with a rim, which lights that edge, and not on a ramp that doesn't start with black. Its fall stays spread evenly over the rows it has: the 30×10 log lit from the north-west is b c b a 9 8 7 6 5 then black down every column, detail 2.00, every row along the axis one rung. The ladder (neighbours at most a rung apart), the rim (a rung more on edge cells facing away from the light) and the lint's specks voted out follow. The tries: bands of 1, 1.25, 1.5, 2, 2.5, 3, 4 and 5 columns, the fall at the turn or 15% of the span either side of it, then starting just past the light's lit share (below) and 5, 10 and 20 points past it; with the glint (its falloff to the plane none or a column a rung, so it is two cells of the top rung ringed once by the ladder: a 2–5 cell spot at every size, where a wider falloff made a 13–15 column bull's-eye on a large dome, which reads as a disc), then without. **Bounds:** a try is in bounds where its black (the darkest rung) is at most the light's shadow (the cells turned from it) plus ten points and its lit plane (the plane's rung and above) at least the light's lit share (`formLight`: the cells it lights as brightly as the plane's rung, the rungs from black to the top taken as the light from none to full). A try out of bounds is never laid while one in bounds is clean. **The bar** is the detail measure: `lint::detail` (distinct looks over 4×2 windows, a test checking it against measured figures) at a mean of 3.6 looks a window or more and under 15% flat windows, each read as the mean over the 8 alignments of the windows on the form's box (the reading at the box's corner, the usual one for a piece, is reported beside it); besides that the ladder lint clean (every rule but the glyph count and noise, cells off the form counting as no neighbour), the lit plane laid, no rung of the fall wider than four cells along the gradient on the turn, at least two shade glyphs, and no seam (a cell lighter than both its neighbours in the row three rows running). The first try in bounds that clears the bar is the form. When none does, the clean try in bounds that comes nearest is laid (narrow rungs, two glyphs, no seam, the plane, the glint, under 15% flat, then detail), then the clean try that comes nearest; when no try is clean, the brush lays nothing. A form gets tries until they have covered about two million cells, so a select-all of 160×400 lays its first dab in under 0.2 s. **The bar is out of reach on most forms under the bounds**, and the brush says so by laying the nearest try in bounds. Before the bounds the brush cleared more by laying black far past the shadow (a 36-across disc 61% black against a 24% shadow). A survey of 384 forms (discs 12–64 across, two ovals, ten cylinders, three L shapes as domes and cylinders; all eight lights; glint on and off; steel) reads, before → after: forms over the shadow plus ten points 159 → 0; clearing the bar at the corner 138 → 35 and over the 8 alignments 103 → 49 (48 clearing the whole bar); by group, over the 8 alignments, discs 56 → 29 of 96, ovals 6 → 0 of 32, cylinders 23 → 16 of 160, L domes 16 → 2 of 48, L cylinders 2 → 2 of 48; median detail 3.26 → 2.62 and flat 4.2% → 9.6%. Discs 12 and 20 across clear (14 of 16 lights with each glint setting); from 28 across none does: the lit plane a light lights as brightly as the rung below the top is a third of a dome, one look a window, so a 36-across disc reads 2.8–3.0 with 11–12% flat from the north-west (black 33% against a 24% shadow) and a 64-across one 1.9 with 34% flat. The fix is a smaller form or a longer ramp. **Large domes miss the detail bar:** the glint as a spot breaks up less of the lit plane than the rings did, so glinted domes from about 28 across read lower still (a 36-across disc lit from the north 2.34 with 23% flat). Over discs 12–64 across in fours, every light, dome and cylinder, glint on and off (448 forms), round 6 leaves 56 clearing the bar (all domes, none over 24 across), as before, with the median detail 2.36 → 2.33 and flat 11.5% → 13%. With iCE off the form's lightest rung is the last one it can write (no bright background) running unbroken up from the darkest, so the ladder never jumps a rung it can't write.
- **Painting the form:** the brush paints the selection's shape (the cells the stroke may paint), or with nothing selected the cells the stroke has covered so far, each cell at the strength of its strongest dab; strength moves a cell that share of the ramp's rungs towards its tone. With nothing selected a stamp that grows the shape works the form out near it, over the covered cells within two dab widths and six columns of its footprint across and a dab's height and three rows up and down (every solve runs on the box of its shape and a ring of cells, not the canvas), and a stamp that grows or strengthens the shape lays again the covered cells within a dab's width and two columns of its footprint and half its height and a row: all the cells the form was worked out over when those hold every cell the image has covered, so a small shape is the whole form as before. A cell further off keeps what the stroke left it, so a long stroke is shaded as a run of forms along it, and a stamp's work is bounded by its size: a test holds a size-5 stamp's most work over a wave to within a quarter between the middle and the end of a 160-column stroke and the end of a 400-column one (32,535, 34,550 and 38,726 cells; laying the whole form again took 673,961, 1,106,897 and 2,891,174), and with a selection its most work after the first dab the same 48 cells on 160×100 and 400×160 (16,879 and 66,514 when the selection's shape was built and compared, and every covered cell laid, at every dab). What the dab actually changes is checked, not the form: the stroke's lint guard (`StrokeLint`, below) reads what its paints would add to the canvas as the stroke began, and while they would add a finding the changed cells within a cell of each new one (all of them when none is that near, as for one glyph and noise) are taken back to what the stroke had left them, so a part dab, a lone selected cell, a one-cell dab or a step that meets an edge far along its row adds nothing, and a dab that can lay nothing leaves the stroke as it was rather than taking back what earlier dabs laid (#723: a size-14 square drag on a flat field went from 149 changed cells to 0 mid-drag, and from 113 to 17; a test now holds every dab to at least half the most the stroke had changed). That costs order independence: replaying a stroke's dabs paints what playing them once does, but another order can paint otherwise (190 of 600 random strokes on small canvases, and 172, 175 and 192 of 400 under mirror X, Y and both; none adds a finding in either order). It works out the selection's form at a stroke's first dab, keyed on the shape's cells and the lightest rung, so a new selection or a cell gone transparent under the lock is a new form. Under symmetry without a selection each image is shaded as its own form, from the cells that image has covered, so a symmetric stroke shades as its images would one by one.
- **Soft:** the ramp shade brush with a falloff (`softFalloff`) measured against the tip's own footprint, and over a stroke against the stroke's own shape: the middle moves its strength's share of four rungs, and from the tip's edge in the cells move a rung, two, and so on, each band a column in from the ends of its row and a row in from the ends of its column, so a band is a cell wide wherever it runs. Each band's corner cell drops to the band outside it, so no cell is both in a band's run across the top and in its run down the side: the lint measures a step's width by the longest run the other way of any of its cells, and a stroke whose dabs drop a row puts a step at the end of every band across the top. The outermost band leaves its corners out, except where the shape runs three cells or fewer one way (no step there is wide enough to matter), and a two-by-two tip, all corners, keeps them, so a small tip or a thin stroke still moves every cell. No cell moves further than all four neighbours (a speck). Hardness is the share of the bands the falloff doesn't use; a hard tip (1) moves every cell of one dab its full strength. Cleaning each tip doesn't keep a stroke clean (overlapping dabs at a bend, a pressure change), so the stroke is shaded again after every dab: each cell wants the depth of the strongest dab that covered it, and moves no further than its band in the stroke's shape so far (the bands above, over the union of the dabs; the canvas edge and cells the stroke may not paint are no edge). Hardness 1 means no falloff inside one dab, but neighbouring cells across a stroke still never differ by more than one rung, so a pressure change ramps. After any dab the canvas adds no lint finding to the stroke's start, on any start and however far along a row or column the finding falls, one glyph and noise included: each solve's candidate is judged by the stroke's guard (`StrokeLint`, below) against the canvas the dabs it kept have left, and since that canvas adds nothing to the start, what the candidate adds is everything new. A finding is the start's by the lint's rule (`LadderIndex`, below, the maintainer's ruling on PR #59): by kind and place, whatever its message says; a wide step when the start had one the same way, on the same line, of the same rung, sharing a cell with it; one glyph when the start shaded with one glyph only; noise when it is within the limit or no higher than the start's. So a dab that would shade a field of one solid rung with a single glyph gives way (a field of a solid rung uses no shading glyph), and so does one that would lift the noise over the limit (shaded cells leave the pixel count, so the lonely pixels left weigh more). Where the guard, reading the tones as they stand, finds a skip, a wide step or a speck the stroke made, the lighter press gives way, each finding by its own cells (the cell or run that moved more; a wide step by its whole run, or where none of the run moved by the dab's cells along its line), lowered a rung at a time; where those can't move, the settling cells nearest it do. One glyph and noise, read over the whole canvas, give way by the whole dab. **Lint-clean wins over painting:** a dab whose cells can't settle without a new finding gives way entirely, every cell where the last dab left it (a size-1 dab on a flat field would be a speck; two cells on a gradient a rung a column skip their neighbours whichever way they go). The brush gives way cell by cell from the whole footprint rather than searching for the largest clean part of it, so it can leave a dab blank that a smaller change would take (a size-5 round dab on a gradient a rung every two rows does; on flat fields a test finds no dab left blank that could have painted). Each cell's tone is counted in rungs from its value when the stroke began, so nothing compounds. A dab's solve is bounded by the dab: it shades again only the cells within 9 of the box of its whole footprint, settles the 4 beyond, and reads bands and the ramp with 13 more of context, so the solve's cost doesn't grow with the stroke or the canvas. Each image of a mirrored dab gets a grid of its own (images whose regions touch share one), so a mirror costs its images and not the box between them. The canvas before the dab and the one being shaded are kept for the stroke and only the cells a solve changes are written, so no dab copies the canvas. The work count (`cellsVisited`) counts every cell read or written: the grids' copies, the band and ramp passes, each solve's passes, each rung read, and once a stroke the guard's start (three passes over the canvas). Tests hold it: a size-41 dab's most work a stamp is the same on 160×100 and 160×1000 (within 2%) and under 170 times its window (the dab and 26 cells each side; a dab that gives way takes a pass over the window a rung, and it gives way more rungs now the guard reads one glyph, noise and wide steps sliding along their line: 159 windows at most under round 7, where round 6 took under 100; a dab that lays nothing is solved a second time, below, and 134 at most since round 9); a mirrored dab within 10% from 160×100 to 1600×100 (X) and 160×200 to 1600×2000 (X and Y); and a wave of 60 size-8 dabs growing at most linearly with W + H over 80×40, 160×100 and 400×160. The guard's judge costs O(W + H) a changed cell (the index's update along the rows and columns through it, and the lines the start had a wide step on read whole), once a step of the give-way loop, so that part grows with the canvas's sides, not its area; taking the guard at the stroke's first dab is a whole-canvas pass. **A stroke never takes paint off:** under Lighten no cell is left darker than it has been during the stroke, and under Darken none lighter; where a solve would leave a cell short of its best, the cell is held there and the solve runs again. A dab that wants nothing deeper than the stroke already wants is skipped, so going back over a stroke at the same or a lighter press changes nothing (tests: Codex's two round-6 repros, and 120 random strokes that scrub back and forth). A dab that lays nothing, and only such a dab, is solved once more, round the dab even when the whole stroke is re-shaded, with the wants of the stroke's cells it hasn't moved, outside its own footprints, set aside, so an earlier dab that laid nothing holds no later one back; they are put back after, so dabs that are each a speck alone still make a line together (#727: on a fire dome with iCE off, a size-3 Darken dab at (29,12) lays nothing and one at (31,13) alone darkens row 13 to 444433344; the first then the second laid nothing, and now paints what the second does alone). That costs order independence: whichever of two overlapping dabs lands first keeps the paint it laid, so dabs within 4 cells of each other can give different tones in different orders (on a row 1 1 1 3, dabs A then B give 1123 and B then A 1114). - **Despeckle:** each cell under the brush that the lint calls a speck (`speckFix`, the same rule) takes the rung most of its neighbours share (the nearest on a tie, then the darker), copied from a neighbour that has it (below, above, left, right; keeping the cell's own transparent flag), and the dab goes over its cells again until none is a speck. Cells are read as the stroke has left them, by rows from the top and left to right, turned over (and the neighbours with them) for a flipped tip. Under a mirror the dab's images are cleaned together: a cell and its images are judged from the same cells and set together, the images read as the mirror of the dab, so a stroke on a symmetric canvas stays symmetric (a test runs 400 random strokes under X, Y and both, the axis on a cell and between two), and images that don't meet clean as they would one at a time. Cells that aren't specks, black, the top rung and cells off the ramp are left alone; with iCE off a bright background reads as off the ladder. Timed on the dev machine (RelWithDebInfo; the hidden `shading brush timings` test, the form's runs above), mean / 95th percentile / worst, the first dab, which takes the guard, included: a wave of 60 unjoined size-8 dabs over a gradient takes 0.04 / 0.01 / 2.2 ms a dab on 160×100 and 0.20 / 0.01 / 11.3 ms on 400×160; random walks of 40 joined size-9 dabs 0.06 / 0.04 / 2.0 ms and 0.26 / 0.04 / 10.1 ms.
- **The lint at a change** (`lint::addedFindings`): the findings at cells a canvas has that another of the same size, differing only at given cells, doesn't, exactly what linting both whole canvases and comparing finds (a test checks it on random canvases and changes). It reads only the change's reach (`changeReach`): the rows and columns through the changed cells and the cells next to them, each to its ends, plus the rows and columns the width rule reads across them (a step's width reads its rung's run the other way, and a column's step isn't judged where a row reported its cell). `findingsAt` gives the findings from given rows, columns and cells. The brushes no longer use it: each keeps a `LadderIndex` a stroke (below).
- **The stroke's lint guard** (`brushes/guard.h`, `StrokeLint`): the soft, form and despeckle brushes each take one at a stroke's first dab, from the canvas as the stroke began, and keep it in the stroke's brush state, so it lives and dies with the stroke and is never carried over an undo, a cancel or an edit between strokes. It holds one `LadderIndex` and the canvas as the dabs it kept left it. `judge(after, changed)` returns what `after`, differing from that canvas at `changed`, adds to the stroke's start by the lint's rule; `keep()` takes it, and a judge not kept is put back at the next. Every change a brush writes to the stroke has been judged and kept, so the preview and the committed edit are the canvas the guard holds, and add nothing to the start. The index's `apply` compares with the canvas it holds, not the start, so wide steps need one more read: one that shares cells with a kept one isn't added to the kept canvas, yet may have slid off the start's along its line a dab at a time, so on lines the start had a wide step on the guard reads the line's wide steps whole (`LadderIndex::wideRungs`, O(W) or O(H)) and matches them against the start's runs. A judge costs O(W + H) a changed cell. Tests: two repros round 6's guards painted (one glyph on a solid field, noise lifted over the limit); 240 random strokes of the three brushes, iCE on and off, under no mirror or X, Y or both, read against the stroke's start over the whole canvas after every dab, add nothing (round 6's guards let 18 soft, 2 form and 2 despeckle strokes of them add a finding); and `wideRungs` matches `checkLadder` line by line.

**Detail**
- **Half-block pencil** with 4-connected stroke mode, so diagonals don't dot (the default; 8-connected is the dock's other choice).
- **Outline brush:** the edge cells under it become the line: the ramp colour next below the level inside them (`lint::outlineRung`), the darkest the ladder lint accepts. The level inside is read once a stroke from the whole stroke-start canvas, so a thin part takes the line of its body however far off, under any dab. Where the darkest would add a finding, the cells to blame step one rung lighter, down to the cell as it was. Each finding is blamed on its own: along its row or column (a wide run, where nothing along it is, on the changed cells across it within the runs blameRuns reads, searched among the trial's changes, so the search costs the changes and not the canvas); a speck on itself first; noise on the changed cells whose own change raises it (the lonely and counted pixels round the cell, with it as tried and as it was); one glyph on the cells that change a shade glyph. A blamed cell beside a darker blamed cell waits for it. Where no step clears noise, the one finding, the line goes back on the index a cell at a time, the cells that raise the noise least alone first, each kept where the noise stays as it was or within its limit: a line raises noise as a whole, its cells taking pixels each other's neighbours count, so no cell of it need raise the noise alone and leaving the nearest cells off first can drop most of the line (20-shades and psyop-radar). Where no step clears another finding only the fewest cells nearest it are left off, not the rest of the line. Where an image's first settle (a click, a stroke's start) writes nothing from three or more covered cells, it settles again carefully: a skip between two changed cells is first the cell more findings involve, else the darker; then each cell left as it was is tried a step darker, alone or with a stepped neighbour, kept only where the whole line still adds nothing. The outline settles again until a round, careful pass and all, writes nothing, so its line is its own fixed point; but a careful pass starts only while the outline has read under 5e7 cells (`detailCellsRead`, about a third of a second on the dev machine), since a pass that writes starts more rounds and each round is O(W + H) a changed cell: on baud-dudes-all (80×2312) a square-161 click at (60,1541) read 2.4e9 cells in 16 s with a careful pass on every round that wrote nothing, and reads 2.8e8 in 2 s with the budget. Pieces of a few hundred rows stay well under it. A fade the line would leave a speck is repaired inward, on covered cells only. No fragments: a piece of line under three cells the lint allows only alone is left off, and so is a corner where the line leaves a covered edge cell, but only from a piece of four or more, so a connected piece of three stays. A fringe takes the line in its black half, outside the shape, when the line is darker than its shape half (with iCE off written the way round that keeps the background dark, or left where it can't be). Where an outside cell lies beside a fringe along its half (left or right of a ▀/▄, above or below a ▌/▐), as at the ends of an ellipse's top and bottom rows, the shape half would still meet the black ground past that line, so the whole cell takes the line first and the half line is the next step lighter (#53). A fringe the line went into, whole or by its half, is line to the fragment rule. Every write is judged by `lint::LadderIndex` (§10, the ladder lint) with the guard identity: a finding is added by place, a wide rung unless it overlaps one of the same rung that was, noise only when over the limit and higher, so a dab that softens a finding or changes only its value is allowed. Each symmetry image (`Dab::image`) keeps its own index, and a mirror image is outlined in its own frame (the canvas mirrored back, glyphs and all) with the stroke's own unflipped dabs. The shown canvas has one more index. The stroke stamps point k of every image, then point k + 1, and once every image of a point has drawn their composite is judged as a whole: where it adds a finding, the cells to blame for it (a skip's darker changed cell, a speck and what is round it, the cells changing a shade glyph for one glyph, the changed cells across a wide run) go back to what the stroke showed, a mirror orbit at a time and in the images too, until it adds nothing; only where nothing to blame clears it are all the images' cells refused, so a Mirror X click can then write nothing. Where images overlap a cell shows the strongest dab's line; on a tie, the image whose frame has the cell in the first half across, then down, then the lower image, so a cell and its mirror cell take mirror images' lines and a mirrored canvas gets a mirrored line. Each dab settles only round its own new cells: the covered cells within 3 of them the stroke has left as they were, against the line drawn so far and 8 more cells of context. A cell the stroke has written stays for the rest of the stroke unless a strictly stronger dab covers it, and a dab that would add a finding adds nothing. A dab's work (`detailCellsRead`, the lint's reads and the copies included) is flat in the stroke's length and O(W + H) per changed cell; each image's first dab copies the canvas and takes its index (a whole-canvas pass). On a RelWithDebInfo build on the dev machine a size-3 rim stroke takes 0.11 ms a dab at 80×40 and 160×100 and 0.17 ms at 400×160 (25,605 and 44,583 reads a dab at the larger two); a size-256 click takes 14, 29 and 77 ms. Work is linear in the canvas's side: Codex's wide-run square (an image's first settle, so careful) reads 172,565 cells at 40 and 991,565 at 320, and Codex's exposed wide columns 75,869 at 40 and 415,229 at 320. A larger click writes no less on the same shape at the sizes 3, 9, 31, 61, 91, 121, 161, 201 and 256: downfall-of-numenor and byzantine-eagle, and lrh-show, durin-gate, avatars-generic-2, 20-shades and psyop-radar, which are over the noise limit already (the size sweep in `tests/test_outline.cpp`). Between other sizes it is not sure where the noise is over its limit: cells the noise fallback keeps apart can be pruned as fragments, so psyop-radar's steel at (20,13) writes 127 cells at size 73 and 109 at 75. A sweep of three clicks each on 304 of funkpower's pieces dips in 14 of 894 sweeps at those nine sizes (15 before the noise fallback), every one adding no finding. Guarantees: a dab adds no finding to the shown canvas; a stroke's dabs again in the same stroke change nothing. Limits: a second stroke of the same dabs over the result adds no finding but can change cells, since a cell written a step lighter before the line beside it was drawn stays for its stroke (88 of 2,400 generated partial strokes), and where the careful budget ran out so can a second click (the baud-dudes-all click above: 42 cells after 305); the line depends on the order of the dabs (follow-up: settle from stroke-start values so the result depends only on the covered set). A mirrored canvas gets a mirrored line from clicks and from unjoined and joined strokes. The careful settle runs on an image's first settle only, so a later dab of a stroke that meets a skip like the crescent's can still be left unlined. Seams (#51): two shapes on the same ramp that touch are one shape to the outline, so by default no line runs between them and they merge. With *Outline the selection* in Tool Options (`OutlineShape::Selection`) the shape is the ramp's cells in the selection and every other cell is outside it, so the selected shape's edge runs along the seam and takes the line there on its own side, the outline colour of the level inside it, as against black; the shape beside it is left alone. With no selection, or one over the whole canvas, it is the outline as ever. The selection is the rule rather than a colour boundary (a jump of two or more levels would line every hard shadow terminator, and two shapes of one colour have no boundary to find) or a flood from the first dab (it needs a boundary rule too, and would leave the line off wherever the flood doesn't reach); a layer can mark the shape once layers do (§5). The seam is settled against the lint like the rest of the line: beside a flat shape or one falling away from it the seam is the full line (W, then w, then W is no skip), but beside a shape that climbs away from it (W, w, then W▒w W▓w W) w is a skip, and the seam takes the next lighter rung, W░w. The lint reads rows and columns and can't tell a seam from a gradient falling through a line (the crescent's W▓w W░w K W▓w is the same sequence), so it has no exemption for seams; one waits on a mask or layer the lint can read. Preview is the commit, one undo step a stroke; selection and alpha-lock hold. Tools menu, Ctrl+Shift+E, Tool Options' ramp and *Outline the selection*.
- **Rim/highlight brush:** brightens only cells on the light-facing edge of the region under the cursor, by one rung, lit from the Brush dock's light direction (`BrushSettings::lightDirection`).
- **Texture stamps:** `lumps()`-style scales, foliage, brick, hoard and noise, seeded and density-controlled.
- **Pattern/glyph spray** for stars, smoke and haze.
- **Clone stamp** and **symmetry** (mirror X/Y, both, radial).

**Common to all brushes**
- Respect layer alpha-lock and selection masks.
- Tablet pressure through `QTabletEvent` maps to size or strength.
- Live preview of the stroke before commit; one undo step per stroke.
- A cell changes once a stroke, with the strongest dab that covered it (below). The form, soft and despeckle brushes are the exceptions: the form brush lays the form near each dab again as the shape grows, the soft brush shades the stroke again round each dab, and the despeckle brush reads cells as the stroke has left them, so a cell painted earlier can take a new tone (a speck an earlier dab cleared can change again when a later dab clears its neighbour). None of them is a pure function of the footprint: a form dab's take-backs keep what earlier dabs laid, a soft stroke never takes paint off (Soft, above), and a despeckle fix depends on the fixes before it, so the order of dabs can change a tone; replaying a stroke's dabs paints what playing them once does for the form and soft brushes, and the same dabs in the same order paint the same for all three. The form and soft brushes count every tone from the canvas as the stroke began, so nothing compounds, and for every brush the preview is what is committed.

In the core (`brush.h`): a stroke is a list of dabs joined by 4-connected lines, with a square or round tip (a round tip's rows count as two columns, and every size keeps at least the rows of a smaller one). The tip is 1 to 256 cells wide: a larger size, set or reached through pressure, is taken as 256, far more than an 80- or 160-column piece needs, so a joining line walks at most a few hundred points beyond the canvas. The unclipped footprint leaves out cells past the ends of int. Only the part of a joining line within reach of the canvas (the canvas grown by the tip's half width) is walked, in 64-bit arithmetic, so a dab far off the canvas costs nothing. The walk is the whole line's own cells: it starts from the point where the line comes within reach, with Bresenham's error term worked out there rather than stepped to, so a stroke paints exactly what stamping every dab of the line would. A joining line is walked from its lesser end (the higher on screen, then the further left) whichever way the stroke runs, stamping back to front when it runs the other way, so a line back over the same two dabs covers the same cells (Bresenham's line from A to B and from B to A can differ by a cell). A cell changes once a stroke, from its value when the stroke began, with the strongest dab that has covered it: a stronger dab (or a larger footprint reaching it) paints it again from that original value, and a weaker or equal one leaves it. So one pass of the shade brush moves a cell one rung however often it is crossed, and pressing harder deepens a cell rather than adding a pass; a build-up toggle may come later. A dab on the same cell as the last stamps again, so pressing harder without moving grows the brush or deepens the cells under it. A stroke gives a preview canvas and one `CellEdit` (the editor's undo type, each change with its before and after), and that edit is the undo step. Pressure scales size (size × p) or strength (rungs × p, rounded, never below one), so pressure to strength changes nothing at the default of one rung a pass; there is no randomness. Until layers exist, the cell's transparent flag stands in for alpha-lock. Symmetry (`StrokeOptions::symmetry`) is part of the stroke: every dab is stamped with its images (`symmetryDabs`), each image joined to that image of the last dab by its own 4-connected line (the images' stamps go in turn, point k of every image and then k + 1, so a brush sees each point's images together), under the same once-a-stroke, strongest-dab rule, so where images overlap (a stroke across the centre) the one that covered a cell with the stronger dab paints it, and on a tie the lower image (the stroke itself first) keeps it, so a cell and its image take the same strength. A dab carries which image it is and whether it is flipped (`Dab::image`, `flipX`, `flipY`); the tip is flipped with it, so an even-sized tip, which reaches a column further right than left (a row further down than up), paints the exact image, and the glyph brush flips its glyph the same way. Mirror X images column x at width − 1 − x, mirror Y row y at height − 1 − y, mirror X and Y makes both and the half turn; all three are about the canvas centre, in integer maths. Radial makes N turns (2–8) about the canvas centre or a set cell. Cells are twice as tall as they are wide, so radial turns on screen: a cell's offset from the centre is taken with its row doubled, turned, and the row halved again, and rounded to the nearest cell, halves down and right (floor(v + 0.5)); so a quarter turn takes two cells across to one cell down. The sines and cosines of the quarter and half turns are exact, and a half turn is the exact both-ways flip, its glyph flipped both ways. A quarter turn (at 4 or 8 folds) turns the glyph brush's glyph as the selection's Rotate does (`rotateGlyph`, clockwise on screen, `Dab::turns`), so ▀ turned a quarter clockwise is ▐; the tip is not turned. Other turns keep the dab's glyph and tip as they are (CP437 has no turned half blocks to match a third or a sixth of a turn), and at 3 or 5–8 folds rounding can leave a turned line with gaps or doubled cells where the turned dabs' lines join. Half-block pixels are already square, so the pixel tools (`symmetryPixels`) turn pixels about the centre in pixel rows with no aspect; a set cell is the centre of that cell, between its two pixels. An image off the canvas paints only what its tip reaches on it; a pixel image off the canvas is dropped. Each image is clipped on its own, so a dab or a pixel off the canvas still has the images that land on it. The images and the lines joining them are kept in 64 bits (`symmetryDabs` leaves out an image that lies beyond int, since a dab can't hold it; the stroke still joins it in 64 bits), so a stroke near the ends of int turns and joins as it would anywhere. The shapes and fill take their pixels through the same images one by one, so at those fold counts a turned shape can gap too. A shape tool rasterises its shape as far as its images can reach the canvas (`symmetryReach`: the canvas, and for radial the box round the canvas turned back by each fold, a pixel wider each way), so a shape dragged past the edge keeps the turned images of its part off the canvas. Typing and paste mirror only in mirror X (the old mirror mode, `CanvasView::mirrored`); the other modes repeat brush strokes, the pencil and the shapes only.

The rim-light brush is in `brushes/detail.h`. It reads the shape under the brush: the cells on the stroke's ramp other than the ground (the ramp's first colour when that is black), as they show (so with iCE off a bright background counts as its blinking dark colour), and the half blocks a shape tool or the pencil leaves at a shape's rim, two ramp colours or one and black. Black, RGB cells, other ramps' colours and blinking half blocks are outside. A half block with one half black is a fringe. A fringe is always an edge cell, and a full shape cell is one when a cell among its eight neighbours on the canvas is outside the shape or a fringe. Off the canvas is not outside: a shape running off the frame has no rim against the canvas edge, and nothing beyond the edge counts towards a normal. A fringe can't go a rung lighter (a half block has one colour a half, and a rung is a shade glyph between two colours), so the rim light leaves fringes as they are, and the rim falls on the full cells in from them: a full edge cell is lit when its own normal faces the light, and nothing lights a cell whose normal faces away. Nor is a cell lit when the neighbour a step towards the light (a step along each axis the light comes from, so from the north-east the cell up and to the right) is a full shape cell while the neighbour a step away is outside or a fringe, whatever its normal sums to. A neighbour off the canvas is neither. The rule checks only that one pair of neighbours, along the light's own step; it doesn't test whether the cell has an open side towards the light, so it doesn't stop every light from behind (see the known limits below). It is there because the window can see more outside on a narrow shape's far side than beside it: the column of a shape two columns wide that faces a one-column gap (three wide across a ▌/▐ half-column gap) has a normal pointing across the shape. Where that gap runs the shapes' full height, open above and below, the rule keeps the column from being lit from across the shape. A shape drawn with the Ellipse tool whose top row is fringes is lit from the north on the row under them; the cells under its side fringes, which face west and east, are not.

The rim-light brush steps a full edge cell one rung lighter (`stepRung`, so iCE off is handled as for the ramp shade brush) when it faces the light. Its outward normal is taken on a grid of 2 × 2 sub-pixels a cell, a sub-pixel half a column wide and a column tall on screen: a full cell is four sub-pixels in the shape, ▀ and ▄ split a cell top and bottom, and ▌ and ▐ split it left and right. A sub-pixel is outside when its cell is outside the shape (the ground and every cell not of the shape), or it is in a fringe's black half; a fringe's coloured half is inside. The normal is the sum of the offsets from the cell's centre to the outside sub-pixels of the cells within three columns' distance (cells at dx² + 4dy² ≤ 9: three columns each way on the cell's row, two on the rows above and below), each weighted a half, in a window round on screen so no direction is favoured, normalised. Weighted so, an outside cell adds twice its centre's offset and a ▀/▄ fringe's black half the offset of its half-block pixel, so full cells and ▀/▄ fringes have exactly the normals of the half-block pixel grid (a cell two pixels tall, a pixel a column square), and a shape of full cells the normals it would have taken a cell at a time. With the fringes' black halves counted, light can't cross a fringe's black half onto the shape beyond it, a fringe on the canvas's first or last row has its own black half outside, and the full row of a bar three pixels tall under a row of fringes faces down (unless another shape lies a black pixel row under it; see the known limits). The window reaches a row either side of the cell, and a fringe row is the shape's last, so a shape whose fringes lie on the canvas's first or last row lights as it would further in. A ▌/▐ fringe's black half is outside in the same way, so a full cell under a ▌ or ▐ whose black half lies against black cells above faces north. A ▌/▐ column is not an empty column to the normal, as its coloured half is inside: with full cells on columns 2–3 and 5–7 and a ▌ on column 4, the normal of (5,2) points east, where across an empty column it cancels. With the rule above, the cells beside a ▌/▐ column between two rectangles (each one to five columns wide, one to eight rows tall) light from every point as across an empty column, but for their top and bottom cells, which can light where across an empty column they don't. Because off the canvas is not outside and the window reaches three columns, a shape with cells on the canvas's first or last three columns can light differently from the same shape further in, where the window finds outside cells there. With ▐ fringes on column 0 and full cells on 1–6, (1,1), (1,4), (2,1) and (2,4) light differently from W, NE and SE than they do a column in; with full cells on 1–3, the middle cells of column 1 face east, not west; and a stem a column wide is lit down its length from NE, E and SE on column 1 or 2, where from column 3 in only its ends light. Up and down the window reaches a row, so only a shape with full cells on the first or last row can light differently. The compass is on screen too, and a cell faces the light when its normal is within about 73° of it (dot product above 0.3), so the lit arc of a disc is centred on the light. A small block reads as rounded: with the light from the north-west a block lights its top row and left column but not their far ends, which face north-east and south-west. It ignores strength and pressure (it is always one rung), and is one pass a stroke under the strongest-dab rule, so crossing a cell again in the same stroke changes nothing. It is an accent: it lights an edge cell one rung without regard to the ladder lint, so it can leave findings such as a rung skip or a speck, and the lint is the check.

Known limits of the rim light (follow-up #54, an exposure-based lit test):
- Canvas edges: off the canvas is not outside, so a shape with cells on the canvas's first or last three columns, or full cells on its first or last row, can light differently from the same shape further in (above).
- ▌/▐ gaps: the cells beside a ▌/▐ column between two shapes light as across an empty column but for their top and bottom cells, which can light where across an empty column they don't (above).
- Counters: a gap closed above and below, as a letter's counter, can have its side walls' top and bottom inner cells lit from the far diagonal. With full cells on columns 10–14 and rows 3–5 and (12,4) empty, (13,4), whose only open side is W, is lit from NE and SE and not from W, NW or SW; (11,4) mirrors it. From those diagonals the neighbour a step away is the counter's top or bottom stroke, which is inside, so the rule doesn't fire.
- Thin bars split by a black half-pixel row: with ▄ fringes on rows 1 and 3 and full cells on rows 2 and 4 (two bars three pixels tall, a black pixel row apart), the interior of the upper bar's full row, such as (10,2), faces N and is lit from N, not S. Its window sees more outside above it than in the black pixel row below, and the neighbour towards N is a fringe, so the rule doesn't fire. The row's end cells, such as (2,2) with a dot of about 0.24 with N, stay unlit from N.
- Grazing cells on rotated ellipses: the rule can leave a cell whose normal faces the light just over the threshold. On an ellipse with semi-axes 9 and 3 columns turned 35°, (5,3)'s normal has a dot of 0.316 with NW, but (4,2) is full and (6,4) a fringe, so it isn't lit from NW. The ellipse's own normal where its edge crosses the cell has a dot of about 0.17 with NW, so leaving it unlit is defensible.

The ladder (`ramp.h`) holds palette colours only; an RGB cell is off every ramp. A shade can be written either way round (B▓A shows as A░B). The brush writes the way that keeps the background dark (0–7) when only one way does, so a piece needs no iCE colours for it; otherwise it keeps the way the cell was written, lighter on top for new shades. Two bright neighbours need a bright background either way. With iCE off the ramp brush never writes such a rung: it reads each cell as it shows (a bright background is its dark colour, blinking, so off the ramp), stops at the last rung short of its target that keeps the background dark, and leaves the cell when there is none (`stepRung` with `ice` false). `cli shade` opens the file as the editor does (`openAsEditor` in `ansi.h`, which `Document::read` calls too: a file without the iCE flag that holds a bright background opens with iCE on, which stays on through the save even when the shading removes the last bright background, and its blinking cells lose their blink, a loss the save counts unless the glyph is blank) and shades with the document's iCE colours, so a non-iCE piece stays non-iCE; `--ice` turns them on first and the save says so, and it refuses to write a piece whose blinking cells would lose their blink to that unless `--allow-lossy`. Step counts saturate at the ramp's ends.

The ladder lint (`lint.h`) measures pixel `noise` (at most 0.02, from smaug's 0.033 → 0.016 despeckle), with each row's trailing black spaces trimmed as in the written file, and adds the ladder rules:
- Shades may only join ramp neighbours; a shade of two colours of the ramp that aren't neighbours is flagged whether or not it blinks, and other ramps' colours aren't judged.
- No shade rung may be wider than 3 cells along the gradient (rungs are 1–3 cells wide *along the gradient*, so a band reads as a turn, not a stripe). Only a step of a gradient is judged: a run of a shade rung, across a row or down a column, with a lower rung at one end and a higher one at the other. Its width is the shorter of that run and the rung's longest run the other way, in cells. A flat field of one shade and the plane at a gradient's end aren't judged; black is ink or the ground, not the gradient's dark end, so a plane that runs into black is a plane at the end, as at the canvas edge.
- No rung skips. Each row and each column is read as a sequence of levels (runs of one rung); a jump of more than one rung between two levels is a skip when the level before it or the one after it goes on the same way, so three or more levels climb or fall together (bands 3, 5, 8). Two solid colours side by side are judged like any other levels, so solid DarkGrey then solid White at the top of a climbing gradient (1 2 3 4 then 12) is a skip. An outline that turns back (10, 11 then 8), two levels meeting (a fold, two planes: solid DarkGrey against solid White with no third level, or White against a w▒K face) and black against anything (ink, seams, the silhouette: black and cells off the ramp end a sequence) aren't skips. The one end level left out of a sequence is the outline brush's line: a level at either end (against black, off the ramp or the canvas edge) that is one cell wide, solid, and in the ramp colour next below the darker colour of the level beside it, so DarkGrey round bands 9 to 12 is clean. Along a diagonal the line is a 4-connected staircase, two cells on a row. Where the level inside changes along the rim, the line may go on in another line colour (any solid colour but black, against the outside), as a lit rim does (craft `buildings.md`). Every other end level is a rung like the rest, a lighter one (a highlight) included, so a single White cell after 1 2 3 4, and 8, 10, 12 between black, are skips.
- No specks (a lone non-black, non-glint pixel reads as dirt): a cell lighter or darker than all of its neighbours on the ladder, judged only where it has three or more, so the corners of a gradient and the ends of a band aren't. Black cells (ink, a rivet, an eye) and the ramp's top rung (a glint, the highlight) are never specks. Pixel noise can't see shade cells, so this is the speckle rule for shading. Known gap: stripes of two shades a column or a row each are not specks (every cell has a neighbour of its own rung), and noise doesn't see them either; an eye for regular repeats is what catches them for now. Known limits the other way: the one-cell peak of a ball that stops below the top rung is a speck (one), and a one-wide diagonal line one rung off its field is all specks. A Bayer-dithered gradient is speckle too (a 4×4 Bayer over rungs 3–9 gives 60), so the gradient tool's ordered dither and this rule have to be reconciled before that tool lands.
- A form needs more than one shade glyph.

A brush that guards against the lint asks what its dab adds, not what the canvas has. `LadderIndex` holds a canvas's whole-canvas findings and moves with it a change at a time. `apply(after, changed)` returns what the change adds as a guard judges it: a wide rung unless the canvas had one the same way (across or down), on the same line, of the same rung, whose run shares a cell with it; a skip unless the canvas had one the same way, on the same line, between the same two cells, or between the same two rungs with each of its levels sharing a cell with the old one's (`LadderIndex::Skip::matches`), so a level grown or shrunk at the boundary moves the skip and it is the skip that was, while a skip of another pair of rungs a cell over is added, and so is one whose level moved past the old one's (#66); any other finding whose place (`LadderFinding::Place`: kind, cell and other cell) had none of that kind; one glyph where the canvas didn't use one glyph only; and noise when it is over `maxNoise` and went up. Past the rungs those rules name, the message and the numbers in it (a rung's width, the rungs of a skip that stays between the same two cells, the noise) aren't part of the match, so a dab that narrows or widens a wide rung at either end, joins two runs or splits one, or lowers the noise, adds nothing; a guard won't flag a finding that gets slightly worse in place, and the lint panel still shows it. A band repainted to another rung is added, and so is a step that moves from a row to a column at one cell. The whole-canvas list (`findings()`, `checkLadder`) compares findings on every field. `added` asks without moving (an apply and the update back, so a guard that keeps most dabs applies and puts the cells back on a refusal), and `addedFindingsOnce(before, after, ramp, changed)` is the one-off that builds an index of `before` (whole-canvas cost; a stroke keeps one index). `wideRungs(across, line)` lists the held canvas's wide steps along one row or column in order, O(W) or O(H), for a guard that compares with an earlier canvas than the one held; `skips(across, line)` and `skipsAdded(across, line, was)` do the same for skips. Both rules are judged against the dab's canvas, and neither is transitive (a level that slides a cell per dab ends up sharing no cell with where it started), so a stroke's guard reads them against the stroke start's lists, not the canvas before the dab, as far as it goes: `StrokeLint` judges skips on the rows and columns within two of a change, and wide rungs on the rows and columns through a changed cell where the start had a wide rung; the Outline brush's composite judges skips that way, but wide rungs only against the composite before it (`apply`), so a run of one rung that slides a cell a composite, each overlapping the one before, is never added, however far it ends from the start's run (steel, a rung-5 run moved from columns 1–4 to 5–8 a column a composite: no finding, where the start's lists would add one on each row). No Outline gesture is known to slide a run so; if one turns up, the composite should read wide rungs as `StrokeLint` does. `maxRung` below 1 is refused (`LintError`), since a one-cell run's steps across and down end at the same cell. `apply` refuses a canvas of another size, and a debug build also refuses one that differs at a cell `changed` doesn't name; an index belongs to one canvas and is taken again after an edit it wasn't told of. Each place has one slot (a cell's shade or speck, a run's start across and its start down for wide steps, so a cell has two, a line's skip list in order along it, and the canvas's one-glyph and noise findings), and a change re-judges only the slots it can reach; on a changed line the old and new skips, and the old and new wide steps (each slot keeps its run's rung), merge in one pass along it. The one-glyph and noise findings are judged on the whole canvas, never on a crop: the index keeps the glyph tally and each pixel's share of the noise (counted, lonely) and updates them a cell at a time, so both are exact. Each row's run widths are bucketed so the longest run the other way is a few word reads, and a change costs O(W + H) reads per changed cell (the end-level rule reads two cells across a line, so the rows and columns within two of a change judge their runs and skips again), plus, for noise, the change in a row's trimmed length (it scans back over blanks to find the new end). Taking the index is a whole-canvas pass, about a third of a second at 400×5000, so a stroke on a very tall piece starts with that stall. The cost is counted in reads (`cellsRead`) and tested to grow linearly with the canvas; a randomized test diffs `apply` against two whole-canvas lints over tens of thousands of changes, a hundred indexes taking 200-400 changes each with undos among them.

`cli shade` runs one pass over a box and prints the check; it exits 0 with findings (a `lint` command comes in Phase 4). `--ramp` takes a name or palette indices; `--ice` turns iCE colours on.

## 15. Text and text styles

Lettering is hand work in every piece so far: TheDraw faces screened by hand for letters that misread at 1×, recoloured by ramp, given shadows and outlines one at a time. ascii.py already has the common looks as styles (`block`, `3d`, `shadow`, `outline`, `mini`, `rainbow`) and a recolour ramp. The editor does this as Photoshop and GIMP do: a Text tool that makes live text layers, and a stack of effects on the layer, saved as presets.

**Text tool** (toolbox and Tools menu, Ctrl+Shift+X; no single key, and the test that no two actions share a shortcut covers it). A click makes a `text` layer (§5) at the cell and puts a text cursor in it; typing, Backspace, arrows and Enter edit the text, Esc leaves it. Clicking an existing text layer edits it. Tool Options (§11) holds the face, case (as typed or capitals), letter and line spacing, alignment and a wrap width in columns. The text stays text until the layer is baked, so changing the face or the style redraws it.

**Faces**, one interface whatever the source. A face turns text into two things: a letter mask (which half-block pixels are ink) and, for TheDraw fonts, the glyphs' own source cells (character, foreground, background), which the mask alone can't hold (a TDF letter can contain ░▒▓ and line-drawing cells). For a source cell the mask is the whole cell: both its pixels are ink when the cell isn't blank, where blank is what transparent paste skips (a space or NUL on black without blink, §4); a space on any other background is ink.

| Source | What | Where it comes from |
|---|---|---|
| Pixel faces | `block`: the IBM PC BIOS 8×8 font at one pixel a font pixel, every ASCII character; `vga`: the bundled IBM VGA 8×16 the same way; `mini`: 4 rows of half-block pixels, 3–5 columns a letter plus 1 of spacing | `block` and `vga` from VileR's Ultimate Oldschool PC Font Pack (CC BY-SA 4.0, already bundled and credited, §14), with the slashed 0 as a credited modification; `mini` drawn for ascii.py by funkpower. Bundled |
| TheDraw fonts (`.tdf`) | Outline, block and colour fonts, read only (§8) | A fonts folder set in Preferences (none by default). Not bundled until each font's licence is checked. The tests use small TDF fonts drawn by funkpower for them |
| FIGlet (`.flf`) | Plain-character faces | Later |

- **Face picker:** each face rendered in the current style, with search and favourites. For the text typed, it marks letters a face can't draw and confusable pairs.
- **Confusable rule:** two characters of a face are confusable when their one-ink 1× masks, aligned left and on the baseline and padded to the wider, differ in at most 2 pixels, or are identical apart from a one-pixel shift. The check runs on the face's own mask, before styling; the sets screened are the known confusables (`ZB8S5O0I1`, `Z2zMWKAH`, `l23456_`). Bundled faces carry the result as data, user TDF fonts are screened when first loaded.

**Text styles** are a stack of effects on a layer, drawn by the core compositor (§5) and redone whenever the text, face or style changes. Each effect has an on/off switch and its own settings. They are drawn in a fixed order, as Photoshop draws layer effects, whatever order the dialog lists them in, and each reads a defined mask:

| Order | Effect | Reads | What it does |
|---|---|---|---|
| 1 | Plate | the text's box | a band of one colour behind the text, a set number of cells round it, for headers and the warning-sign look (recolouring) |
| 2 | Glow | the letter mask grown by the outline | a halo walking the ramp's shading ladder outwards from the colour next to the letters down to the ramp's darkest colour (black for every bundled ramp), one ladder rung a step, so each shade joins ramp neighbours (§10); drawn on the plate, or on black where there is none |
| 3 | Shadow | the letter mask grown by the outline | a drop shadow (direction, distance in pixels, colour) or a 3D extrusion (ascii.py's `3d`) |
| 4 | Outline | the letter mask | a one-pixel half-block ring, or a ring of cells, in a colour |
| 5 | Fill | the letter mask; source cells | flat colour; a ramp across the letters by row or column that steps through the ladder (solid, then the ░▒▓ rungs, then the next solid), so neighbouring colours are always ramp neighbours, with the ░▒▓ rungs on full ink cells only and a ▀/▄ fringe taking the solid ramp colour nearest its position; one ramp colour per letter (rainbow), with each letter's colour kept off its neighbours' by the outline or a blank column. A row gradient steps by pixel row (two to a cell), a column gradient by cell column. On TDF source cells Fill keeps each cell's character and maps its colours onto the ramp by rank, dark to light, as ascii.py's `recolour` does |
| 6 | Shade | the letter mask, full cells only (a TDF source cell only when it is █) | fills full ink cells with the ramp's ladder (§10 `stepRung`); a cell only half ink (a ▀/▄ fringe) keeps the Fill colour, as the rim light keeps fringes |
| 7 | Bevel | the letter mask, full cells only (a TDF source cell only when it is █) | lights the stroke edges facing the light one rung, by the rim-light rule (§10), with Tool Options' light direction; fringes and colours off the ramp are left as they are |

- **iCE off:** Fill and Glow write each rung as `stepRung` would with iCE off (§10): where a rung needs a bright background they stop at the last rung that keeps the background dark, as the ramp shade brush does, so they never write a rung the ladder lint would read as a skip. A preset whose look needs a bright-to-bright interval (two bright ramp neighbours, such as LightRed to Yellow on fire) says so (`"ice": "required"`); with iCE off it is shown disabled in the Library and the Layer Style dialog, and its fixtures run with iCE on only. Every other bundled preset runs its fixtures with iCE on and off.
- **Effects stack like layers:** within a styled layer each effect is drawn over the ones before it by the compositor's rules (§5), so where two effects share a cell the later one wins, and with iCE off it keeps its colour and the half under goes dark, as the upper layer does.
- **Effects don't feed each other's masks,** except that Glow and Shadow are grown by the Outline when it is on, so a shadow falls from the outlined letter.
- **On other layers:** the same stack can be applied to a cells or pixels layer. On a pixels layer each ink half-block pixel is one mask pixel; on a cells layer each non-blank cell (as transparent paste reads blank, §4) is a full-cell mask pixel.
- **Lint:** the styled result is art like any other, so the ladder lint judges it. The Layer Style dialog shows its findings live, and a bundled preset ships only if its fixtures pass (below), the 407-byte line limit included: a preset too dense for it at 80 columns (a heavy Chrome or Gold 3D) is thinned until it fits or isn't shipped.
- **Presets** are saved stacks: Gold 3D, Shadow and Outline (ascii.py's), Chrome, Fire, Ice, Neon, Rainbow, Warning sign and Masthead to start. They name ramps, not colour numbers, where they can. They are files in the Library (§12): `<slug>.style.json` holding `{"kind": "text-style", "name", "category", "tags", "ice" (optional, `"required"`), "effects": [...]}`, recognised by the `.style.json` suffix and the `kind` field, so the Library scan never takes one for a stamp sidecar. `library list` shows them with their kind, and `library check` validates them (known effects and settings, ramps that exist) and renders each one's thumbnail sample.
- **Layer Style dialog** (Layer > Layer Style…, or double-clicking a layer's effects in the Layers dock): the effect list with switches on the left, the selected effect's settings on the right, a live 1× preview, and Save as Preset… (to the user Library). The dialog also shows the IRC bytes of the widest line (the encoder, §8), the lint findings and the confusable warning.
- **Undo:** a run of typing (until the cursor is moved, another command runs or the text tool is left) is one undo step, as in a text editor; changing a Tool Options setting, the face or the style stack is one step each. Each stores the layer's properties before and after (not cell deltas, which can't bring back the source text); undoing one restores the text and settings, and the layer redraws from them.
- **Bake** turns the layer's styled result into plain cells and clears its style, for text, cells and pixels layers alike; it is one undo step, and undoing it gives back the live layer with its text, face and stack.
- **Project file (§6):** a text layer's `layers/<id>.json` keeps its text, Tool Options settings, face and style stack. A pixel face is named. A TDF font is named and copied into the project (`fonts/<sha256>.tdf`), so the project opens the same on any machine and with the font file gone; the copy is what the layer uses. A styled cells or pixels layer keeps its stack beside its cells.

**Fixtures** (`tests/data/text/`, funkpower's own):
- **Words:** `ZB8S5O0I1`, `Z2zMWKAH`, `l23456_`, `funkpower`, each on one line, and the sentence `the quick brown fox jumps` with a wrap width of 80 columns. Words wrap at spaces; a word longer than the wrap width breaks at the character that would cross it. Text starts at the layer's column 0 plus its left margin, with the face's own letter spacing. Each line plus its margin on each side must fit 80 columns with nothing clipped, where a side's margin is the outline's width plus the largest of the glow's width, the shadow's distance or the 3D extrusion's depth on that side, plus the plate's padding.
- **Faces:** each bundled pixel face (`block` and `vga` are 8 columns a character, so the 9-character words fit with up to 4 columns of margin a side), and three TDF fonts drawn by funkpower for the tests (outline, block, colour; the colour one with ░▒▓ cells in its letters), each at most 8 columns a glyph and covering `A`–`Z`, `a`–`z`, `0`–`9` and `_`.
- **Per preset, per word, per face, iCE on and off (iCE on only for a preset marked `"ice": "required"`):** the ladder lint passes and every line is at most 407 bytes.
- **Round trips:** save and reopen give the same text, settings, face, stack and visible cells; after reopening, changing the style redraws from the text. Editing the text, then undo and redo, restore the text and the rendering each time. Bake, then undo, gives back the live layer. A preset saved and reloaded from the user Library has the same stack.
